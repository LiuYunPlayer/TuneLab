# 文件类型图标

TuneLab 关联的文件类型在资源管理器里用的图标。产物是 `TuneLab/Assets/FileIcons/*.ico`，
随程序部署到安装目录，由安装器把 shell 的 `DefaultIcon` 指过去（见
`TuneLab.Setup/Core/FileAssociation.cs`）——**不是** exe 自身的图标，工程文件因此与应用可分。

| 图标 | 后缀 | 构成 |
| --- | --- | --- |
| `TuneLabProject.ico` | `.tlpx` 工程（默认保存格式，紧凑二进制） | 品牌记号 + 深蓝黑纸面 |
| `TuneLabProjectJson.ico` | `.tlp` 工程（JSON 文本形态） | **同一份记号** + 红棕纸面 |
| `TuneLabExtension.ico` | `.tlx` 扩展包 | 方角的正视闭盖盒 + 正面居中的 T |

三个后缀都注册了 shell 关联，双击 `.tlx` 直接进安装流程（`App.HandleArg` 按后缀分流到
`InstallExtensions`，否则会被当成工程打开而报错）。

## .tlx 的容器造型

`.tlx` 是个 package（zip 里装着插件），不是文档，所以容器不用折角纸。定稿是
**`box-front-sharp`**：方角的正视闭盖盒，正面正对观者所以 T 印上去零形变，顶上一片向后
收窄的盖交代厚度；不倒圆 —— 这个造型硬朗才像盒子。

其余造型留在脚本里，靠 `EXT_STYLE` 或 `--ext-style` 可切（都是当初比过的备选）：

| 值 | 说明 |
| --- | --- |
| `box-front` | 同定稿但整体倒圆。**盖与正面共用一条外轮廓再切分**，所以圆角接得上 —— 两片各自倒圆的话，正面顶角往内收、盖子下边却是直的，轮廓就错开了 |
| `open-box` | 正视开盖：两片盖从中线向左右外翻，「包」的语义最明确，代价是箱体变矮、重心偏下 |
| `isometric` / `isometric-top` | 等距立方（尖角），T 分别印在朝左那一面 / 盖顶。盖顶那版两个方向都被斜切，T 容易读成「倒的 L」 |
| `carton` / `carton-taped` | 纸箱正面 + 盖缝 + 方块阵，后者再加一条封条 |
| `page` | 最早的折角纸，语义不对（package 不是文档），留作对照 |

**等距立方为什么是尖角**：不能给三个面各自倒圆 —— 相邻面在棱上会各自往回缩，棱角处就
露出背景，圆角矩形拼不成圆角立方体。真要倒圆得先把整个立方体的外轮廓（一个六边形）整体
倒圆，再用从三棱交点出发的三条射线切成三个面（`ISO_ROUND` 非零就走这条路）。不过这个造型
本来不带圆角更好。

16/20/24 那三档另画：定稿造型对应 `_px_boxfront()`（方角箱体 + 顶部一条略窄的盖 + 正面
一个纯 T）；`carton` 系列对应 `_px_carton()`；等距立方在这个尺寸画不出来，退化成纸箱。

## 两种工程文件为什么用纸面颜色区分

区分手段刻意放在**纸面**上，不动记号。`.tlp` 的纸面是把 `.tlpx` 的纸面
**只旋色相 +120°（`JSON_HUE_SHIFT`）、饱和度与明度原样保留**得到的红棕
（`#523A3D → #1F181A`）—— 手挑色值会悄悄比另一套更饱和（第一版青绿就是这么跑偏的），
按规则派生则两种纸的明暗质感完全一致。选红棕不只是为了区分：`.tlp` 是更老的那个格式，
旧纸/古典的调子正合适。

其余理由：

- 记号是品牌资产，换色相或加东西就不再是原样；纸面换色则记号一个像素都不用改。
- 纸面是大面积色块，**16px 也一眼分得出**。角标（右下角小徽章）在 256/128 上很好看，
  但实测 32px 起就糊成一个小色块、16/20/24 那三档根本画不出来——等于只有大图标能区分。
- 曾经试过的其它路子：去饱和/同色相提亮的纸面与 `.tlpx` 太像，单看认不出；裸横线角标
  形状散，像污点。

配色在脚本顶部的 `PAPERS` 里，两套各含纸面渐变、折角、手绘档实色。

## 记号来自素材本体

**优先路径**：把无背景的记号素材放成 `tools/icons/mark.png`，脚本直接用它——一步图像
处理都没有，画质就是素材本身。规格：

- PNG，带直通 alpha（非预乘），**不含背景、边框、外投影**（投影在新纸面上不匹配）
- 尽量大，≥1024 px 宽即可（成品最大帧 256，纸内记号约 146px，一律只做下采样）
- 画面里只有记号本身（T + 头梁弧 + 耳罩）；四周留多少空白都无所谓，脚本按 bbox 裁
- 若只有矢量源，导出成上述 PNG 即可——脚本不解析 svg

同目录的 `mark-shape.svg` 是记号的**纯色形状**矢量版（单色轮廓），当前没有参与生成，
存着备用：需要单色版记号（比如 UI 内嵌、单色印刷、或将来给小尺寸做矢量简化）时从它出。

**回退路径**：没有 `mark.png` 时，从 `TuneLab/Assets/TuneLab.ico` 的最大帧把记号反混合
抠出来（背景拟合成二维二次多项式 → 色距给 alpha → 剔掉记号脚下的投影 →
`F = B + (C-B)/a` 还原前景真色）。这条路下改了应用图标、重跑脚本，文件图标跟着变。

纸面（深色折角纸）和扩展包的容器/方块阵是脚本画的矢量。

### 折角

- **折角是等腰直角三角**，直角在折痕尖端，斜边与纸形轮廓的斜边同向。它整体沿斜边法向
  平移 `FOLD_OVERLAP/√2`，为的是盖过纸形轮廓自己的抗锯齿边。
- **纸面与折角在不透明的 RGB 层上合成**，最后由纸形 mask（`paper_mask`）一次裁出轮廓：
  全图只剩这一条 alpha 边界。所以折角平移出界也无所谓（自然被裁），斜边上也不可能出现
  「两层 alpha 相加不到 1、缝里透出背景」的黑线。
  · 试过让折角顶点沿纸边滑动来避免出界 —— 三角就不再是直角，折痕尖端变钝。
  · 试过整体平移但不统一裁剪 —— 顶点探到纸外，折痕与纸边交界处冒出一小块。
- **折角画两遍**：一遍在纸面同层，记号之后再来一遍（`fold()`，alpha 裁到纸形）。折起来的
  是纸的背面，物理上它必须遮住印在其下的记号。svg 侧同样画两遍，两遍都 `clip-path` 到纸形。
- **圆角只属于纸原本的角**：左上、右下、左下三个是裁切出来的，倒圆；上边与斜边、斜边与
  右边这两处交界是**折叠**形成的，不该磨圆，是 135° 的尖角。顺着这个道理，折起三角的
  直角顶点其实就是**原纸的右上角**被折下来的那个角，所以它跟其它纸角用同一个半径 `rc`
  （因此全脚本只需要一个圆角半径）。纸形与折角共用一份圆角多边形定义
  （`paper_poly` / `fold_poly` + `rounded_poly_points` / `rounded_poly_svg`，位图与
  svg 同源）。
- 纸面的受光描边在斜边那一段**挖掉**，折角也不另画斜边高光：那里的边界由折角负责，
  多画只会在 45° 上留一串锯齿亮点，而折角本身已经比纸面亮一档。

### 画质

- **实心区零损失**：抠图路径下 a=1 时反混合按定义就等于原像素，实测最大差异 0.000
  （记号约 77% 的像素在此列）。只有最外一圈半透明像素在数学上不精确——那里
  `(C-B)/a` 会放大背景估计误差、把背景色掺进边缘，所以颜色改从实心区**向外扩散**
  得到（`spread_color`），alpha 仍由色距给出，边缘的柔和过渡不受影响。
- **只下采样一次**：记号一律从最大的一份缩到位，而不是「取同尺寸那一帧再按构图缩
  0.83」——后者是两次重采样，且 0.83 这种接近 1 的比例最伤锐度（实测 48px 档边缘能量
  低 18%）。`base_mark()` 带缓存，全过程只取一次。
- 没有有损压缩：ico 内每帧是 PNG，缩放只用 LANCZOS 下采样，从不放大。

## 重新生成

```
python tools/icons/gen-file-icons.py                        # 写 ico + svg
python tools/icons/gen-file-icons.py --preview preview.png  # 附带多尺寸 / 双底色对照图
```

依赖 `pillow` 与 `numpy`。改完记得重新 build——ico 是 `CopyToOutputDirectory` 的 Content，
不重新构建则安装目录里还是旧图标（症状：资源管理器图标没变；Windows 的图标缓存也可能
需要重登录或 `ie4uinit.exe -show` 才刷新）。

`*.svg` 同样**由脚本生成，请勿手改**：容器是矢量、记号是嵌进去的同一份位图，所以 svg
不可能与 ico 脱节。扩展包的 svg 按当前 `EXT_STYLE` 出图，换到没有 svg 实现的造型会
**直接报错**（`write_svg` 里 `NotImplementedError`）——宁可报错，也不要默默写出一个与
ico 不一样的 svg。改形改色都改脚本顶部的常量（`PAPERS`、`JSON_HUE_SHIFT`、`PAPER_W`、
`MARK_FILL`、`PX_MARK_FILL`、`EXT_STYLE`、`ISO_ROUND`、`FOLD_BLEED`、`doc_geom`、
`BOXF`、`OPENBOX`）。

## 为什么 16 / 20 / 24 px 是另画的

这三档位图缩下来只剩一团灰雾——源 ico 自己的 16px 帧同样如此，它也是缩出来的。所以这几档
重绘为纯矩形，并**去掉头梁弧**：它是整个记号里唯一的曲线，在这个尺寸必被灰化。全是矩形、
边界落在整像素上，因此锐利。32px 起才用位图记号，分界线是脚本里的 `PX_MAX`。

比例和配色不是写死的，而是 `mark_metrics()` **从素材量出来**的：横杠宽、横杠高、竖杠宽、
耳罩宽高、横杠中线在记号高的百分之几、以及金属与耳罩的实色。写死的话，换一版记号就会
悄悄失真（这次换素材，宽高比就从 1.20 变成了 0.90）。
