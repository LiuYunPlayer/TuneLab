# 编辑器层 G2P 总闸（AutoGeneratePronunciation）测试用例

覆盖本切片：把「录入歌词时由编辑器做 G2P（汉字→拼音 / 假名→罗马音）填进 note 发音字段」从**恒定行为**
改成**一个可关的设置**，并去掉读取期的第二层猜测。三条改动点：

- **写入期**：`Note.DataLyric.Set` / 录词框按 `Settings.AutoGeneratePronunciation` 决定「补填 G2P 值」还是
  「只清空发音覆盖」。判据挂在数据层 setter，故录词框 / 单 note 输入 / 脚本 / agent 写歌词全部统一。
- **读取期**：`INoteExtension.FinalPronunciation()` 不再拿编辑器拼音候选表首项兜底 —— 发音口径**只看数据**
  （非空 `Pronunciation` = 显式覆盖；空 = 歌词原文直达引擎、由引擎自行 G2P）。
- **设置面**：`SettingTab.Editing` 新增一行（默认**开启**，15 语言标签），随 settings.json 读写、agent 可枚举可写。

只测本切片受影响范围。**不复测**音素显示/布局基线（`PHONEME-*-TEST-CASES.md`）、延音判定
（`IS-CONTINUATION-CHAIN-TEST-CASES.md`）、脚本发音覆盖读写（`AGENT-PART-NOTE-PARAM-WRITE-TEST-CASES.md` 用例 1）
—— 那些通道本身未改，本切片只改「发音字段由谁填、空值怎么解释」。

## 前置

- `dotnet build TuneLab.sln -c Debug` 已通过（本切片不动 SDK 面，**已安装的样例插件 tlx 无需重新打包/安装**）。
- 本机已安装样例 voice 插件 **V1 Test Voice**（`V1.Voice`）与 **Legacy Test Voice**（`Legacy.Voice`）。
  若尚未安装：关掉 TuneLab → `pwsh tests/pack-tlx.ps1` → `pwsh tests/install-tlx.ps1 V1.Voice Legacy.Voice`。
- **观察窗口**：这两个样例插件都把收到的 `Lyric` **原样当音素符号**输出，所以钢琴窗底部音素带直接显示
  「引擎收到了什么」——收到 `重` 显示一个音素 `重`；收到 `chong` 显示 `c`/`h`/`o`/`n`/`g` 五个音素。
  用例里说「音素带显示 X」即指此处。
- 工程：新建工程，一条轨挂 **V1 Test Voice**，part 内放 4 个空白音符（供录词）。

> 提示：改歌词 / 改发音都会触发重合成，音素带更新可能滞后一两秒，属正常。

## 1. 设置项本身

1. 开设置窗 → **Editing** 页，应见新行 **Auto Generate Pronunciation**（中文界面：「自动生成发音」），
   复选框**默认勾选**。
2. 取消勾选 → 关设置窗 → 重开设置窗，仍为未勾选（活值即时生效，无需重启）。
3. 退出 TuneLab → 看 `%APPDATA%\TuneLab\settings.json`，应有 `"AutoGeneratePronunciation": false`。
   手工把该键删掉再启动 → 复选框回到**勾选**（缺键退默认，不影响其它键）。
4. 切几种界面语言（zh-CN / ja-JP / ru-RU 任选）→ 该行标签为对应译文，非英文原文。
5. Agent 侧栏问「列出编辑相关设置」→ `list_settings` 应列出 `AutoGeneratePronunciation`，
   带说明（关掉后歌词原文直达引擎、由引擎自行 G2P；只影响此后录入的歌词，已存工程里的发音不动）。
   再让 agent 把它关掉 → `set_setting` 成功，设置窗复选框同步变化。

## 2. 开关**开启**（既有行为回归，默认档）

1. 勾选开关。选中 4 个音符 → 录词框输入 `你 好 世 界` → 确定。
2. 每个音符上方两行：第一行歌词 `你`，第二行发音 `ni`。
3. 音素带显示 `n`/`i` 等**拼音字符**（= 引擎收到的是 `ni`，与 1.x 行为一致）。
4. 单个音符双击输入歌词 `重` → 第二行显示 `zhong`（单字首选），音素带为拼音字符。
5. 日文路径：输入 `か` → 第二行 `ka`，音素带 `k`/`a`。
6. 点第二行发音标签 → 弹出候选发音菜单（多音字如 `重` 应有 `zhong`/`chong`）→ 选 `chong`
   → 第二行变 `chong`，音素带随之变化。

## 3. 开关**关闭**（新行为：原文直达引擎）

1. 取消勾选开关。选中 4 个音符 → 录词框输入 `你 好 世 界` → 确定。
2. 每个音符**只有一行歌词**（`你`），**没有第二行发音** —— 发音覆盖为空。
3. 音素带显示**汉字本身**（`你`）—— 引擎收到的是原文，可按自身音系/方言 G2P。这是本切片的核心验收点。
4. 单音符双击输入 `重` → 无第二行，音素带显示 `重`。
5. 日文 `か` → 无第二行，音素带显示 `か`。
6. 英文/罗马字歌词 `hello` → 无第二行，音素带显示 `h`/`e`/`l`/`l`/`o`（原文即拉丁字母，行为与开关无关）。
7. 用 agent / `run_script` 给某音符写 `note.pronunciation = "chong"` → 第二行出现 `chong`、音素带跟着变
   （显式覆盖通道不受开关影响，开关只管录入期自动填充）。

## 4. 改歌词清覆盖 + 撤销对称

1. 开关**关闭**。承用例 3.7 那个有 `chong` 覆盖的音符，把歌词从 `重` 改成 `轻` →
   第二行**消失**（旧覆盖被清，不残留 `chong`）。
2. Ctrl+Z → 歌词回 `重` **且** 第二行 `chong` 一并回来（一次撤销回滚两个字段）。Ctrl+Y 再确认前进也同步。
3. 开关**开启**下重复：`重`（覆盖 `chong`）改成 `轻` → 第二行变 `qing`（新字的 G2P 值，非旧 `chong`）；
   Ctrl+Z 一次回到 `重` + `chong`。
4. 录词框一次录 4 个字 → **一次** Ctrl+Z 应整批回滚（歌词 + 发音同批）。

## 5. 存量工程（本次有意不做迁移）

1. 找一个 1.x / 早前存的工程（note 的 pronunciation 普遍存有自动填的拼音），
   **开关关闭**状态下打开。
2. 预期：这些音符**仍显示第二行拼音**、音素带仍是拼音字符 —— 存量数据原样保留，开关不追溯已存工程。
   （设计取舍：加载期不猜、不静默改用户数据。）
3. 在该工程里新录一批歌词 → 新录的没有第二行、音素带为原文。两者在同一工程内并存，符合预期。
4. 想让老工程也走原文：用 `run_script` 批量把 `note.pronunciation = ""`（脚本面已支持）→
   这些音符第二行消失、音素带变原文，且可整批撤销。

## 6. legacy 插件路径（已知限制，本次有意未改）

1. 把 part 音源换成 **Legacy Test Voice**（`Legacy.Voice`）。
2. 开关**开启** → 录词 `你好` → 音素带显示拼音字符（= 老引擎收到 `ni`/`hao`，与 1.x 逐字一致）。**必须通过。**
3. 开关**关闭** → 录词 `你好` → 音素带显示汉字（老引擎收到 `你`/`好`）。
   **这是已知取舍**：本次未在 legacy compat 层复刻编辑器 G2P，所以关掉开关后，不认识汉字的老引擎会拿到原文。
   记录现象即可，不算失败项 —— 依赖老中文引擎的用户应保持开关开启。

## 7. 空引擎 / instrument 边界（回归）

1. part 不挂任何音源（内建空引擎）→ 录词、改词、开关开关切换，均不应崩、不应卡在留白态。
2. part 挂 instrument 音源 → 音符上显示音名（如 `A4`）而非歌词/发音，开关对其无任何影响。
