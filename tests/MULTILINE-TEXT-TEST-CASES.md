# 多行文本（`TextBoxConfig.WithMultiline`）· 测试用例

> 范围：`TextBoxConfig` 新增的多行形态——插件声明 `.WithMultiline(最多行数)` 后，宿主把该字段渲染成多行框
> （`MultilineTextInput`，AvaloniaEdit 那个），值仍是**一个** string、换行在里面。
> 只测这个形态带来的新行为：框的长相与滚动、三态（含多选占位）、单行↔多行的动态切换、掩码冲突的降级。
>
> **值链路已自动化**：`pwsh tests/headless/multiline-text.ps1`（17 项，全绿）覆盖了措辞两支（封顶时带行数 / 0 = 不封顶不带）、
> 换行穿过 JSON → PropertyValue → 脚本 `main` 的往返、默认值本身带换行、扩展设置那条入口。
> 人工只需跑下面这几组——它们全是控件交互与界面绑定，没有自动化路径。

## 前置（已为你备好）

- 已 build + pack + 预装：`tests/tlx/v1-settings.tlx` → `%AppData%/TuneLab/Extensions/`，直接开 App 即可。
- 夹具「V1 引擎设置演示」新增一项 **启动备注**（`startup_notes`）：多行、**最多 4 行**——框贴着内容长
  （一行内容就一行高），到 4 行封顶、其后框内滚动。（`0 = 不封顶` 是缺省值，由无头用例覆盖。）
  同面板的**模型路径**（单行）与 **API 密钥**（掩码）作回归对照。
- 日志：`%AppData%/TuneLab/Logs/TuneLab_<时间>.log`（最新一个），夹具在 `ApplySettings` 里把该值打出来，
  换行以两字符的 `\n` 字面量呈现（日志逐行，真换行会把一条拆成多条）。

---

## A · 长相与输入

打开「设置」→「扩展」→「V1 引擎设置演示」，找到**启动备注**。

- [ ] 清空内容 → 框**只有一行高**（贴着内容，不白占 4 行）；上面的「模型路径」是单行框，对照着看。
- [ ] 敲回车能换行（不是提交、不是无反应），每加一行框**跟着长高一行**。
- [ ] 打一段很长的、不带换行的文字 → **自动折行**，不出现横向滚动条（折出来的行同样算进高度）。
- [ ] 内容超过 4 行后，框**停止长高**，改为框内纵向滚动；滚动条是那条统一的浮层细条。
- [ ] 光标移到可视区外（按 End / 方向键往下走）时，视图**跟着光标滚**，够得着后面的内容。
- [ ] **不闪退**（回归项）：在框里打几个字，然后点到别的控件 / 切到别的窗口 / 直接关掉设置窗——
      失焦即提交，曾在此崩过（程序化回灌被当成用户输入，在提交流程中途重入绑定）。

## B · 存取与撤销

- [ ] 填两三行内容 → 关设置窗 → 重开 → 内容还在，**换行位置不变**。
- [ ] 重启 App → 内容仍在；日志里 `[V1.Settings] ApplySettings: startup_notes='...'` 与界面一致，
      换行显示成 `\n`（说明存的是一个带换行的字符串，不是被拆开或吞掉）。
- [ ] 用文本编辑器看 `%AppData%/TuneLab/Configs/ExtensionSettings.json`：该字段是**普通 JSON 字符串**，
      换行以 `\n` 转义（与单行字段同形，没有新结构）。
- [ ] 在框里改一段 → 点别处失焦 → **Ctrl+Z 撤销**回到改前，**Ctrl+Y 重做**回到改后（与单行字段同一条撤销路）。

## C · 三态（多选时的占位）

前置：`v1-suite.tlx` 已装好。新建工程 → voice 引擎选 **TLSuiteVoice** → 声库选 **`[v1-suite] Voice`**
（基线声库，**不是** `Conditional`）→ 画几个音符。note 属性面板里的 **memo** 就是多行字段（最多 3 行），
同面板的 `label`（单行）作对照。这组测的是 `MultilineTextInput` 的 `DisplayMultiple`。

- [ ] 给两个音符的 **memo** 填**不同**内容，再框选这两个 → 框内**正文为空**，只显示灰色占位 **`(Multiple)`**。
- [ ] 此时点进框直接打字 → 从**空白**开始编辑（不会把 `(Multiple)` 这几个字面量编进去），
      提交后两个对象都写成新值。
- [ ] 选中两个 memo **相同**的音符 → 正常显示那个值（不是 `(Multiple)`）。
- [ ] 对照：同一组多选下，单行的 `label` 字段同样显示 `(Multiple)` 占位——两种控件的三态一致。

## D · 单行 ↔ 多行的动态切换

夹具没有"随其它值切换单/多行"的字段，故这组用**脚本入参窗**验（`getInputConfig` 会随值重算）：
新建脚本工具，`getInputConfig` 里按某个开关返回 `TextBoxConfig.create('')` 或 `.withMultiline(4)`。

- [ ] 切换那个开关 → 同一字段在单行框与多行框之间**换控件**，面板其余行不闪、不重排。
- [ ] 切换前框里的值在切换后**还在**（值绑的是同一个字段，换的只是控件）。

## E · 掩码冲突的降级

- [ ] 脚本里写 `TextBoxConfig.create('').withPassword().withMultiline(3)` → 该字段渲染成**单行掩码**框
      （掩码没有多行形态，故以掩码为准）。
- [ ] 日志里有一条 `TextBoxConfig declares both IsPassword and IsMultiline ...` 的告警（每进程只说一次）。

## F · 回归（既有文本字段不受影响）

- [ ] 「模型路径」仍是单行框，回车不换行；「API 密钥」仍是掩码单行框。
- [ ] 属性侧栏里既有的文本类属性（如音素符号、歌词相关输入）长相与行为如常。
- [ ] 歌词录入板与 Agent 输入框（同样用 `MultilineTextInput`，但走的是自己的路子）一切如常：
      占位提示语还在、AutoGrow 的框仍随内容长高。
