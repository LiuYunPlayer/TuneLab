# Agent 问用户（`ask_user_question`）测试用例

覆盖新增的第 24 个工具：agent 在**本轮之内**问一句、等到答案再继续。
选项与自由文本**各自独立**（可以只选、只写、或两者都有），单选/多选两种模式，不设超时。

**前置**：代码已构建、应用已重启（新工具要重建工具表才注册）。测试时直接对 agent 说
「先问我一个问题再动手」之类即可诱导它调用；或者让它做一件真有歧义的事（见用例 5）。

---

## 1. 单选：圆点 + 提交

让 agent 问一个带 3 个选项的单选问题（例如「用哪种方式加和声」）。

**期望**：
- 卡片出现在**本轮的步骤流里**，且在它自己那次 `ask_user_question` 工具块的**下方**（不是上方）。
- 选项前是**圆点**（不是方框）—— 单选样式。选中时是**圆框保持白色、中间多一个彩色圆点**，
  不是"整圆被填成蓝底 + 中间白点"（那是 CheckBox 那一路的样式，用在单选上会认错）。
- **点整行**（不只是那个 16px 圆点）就能选中；hover 时整行有淡淡高光。
- 选中一项后再点**另一项** → 前一项自动取消（互斥）。
- **再点已选中的那一项 → 可以取消**（本卡片允许一个都不选）。
- 点 [提交回答] → 卡片**立刻变成只读留痕块**：选项还在、你选的那项打着勾且文字为白色、**没选的压暗**，
  没有文本框也没有按钮。此时**去点选项应该毫无反应**（旧的交互控件已被整块换掉，不是"逐个禁用"）。
- agent 收到答案后**继续在同一轮里干活**（不需要你再发消息）。

## 2. 多选：方框 + 多个一起交

让 agent 问一个多选问题（例如「这几条轨都要处理吗」，给 3-4 个轨名）。

**期望**：选项前是**方框**（CheckBox 样式）；可同时选中多项、互不排斥；提交后 agent 的回报里能看出**选了哪几项**。

## 2b. 多选：一个都不选也能提交

同上的多选卡片，**一项都不勾、文本也不写**，直接点 [提交回答]。

**期望**：**按钮是可用的**（不置灰）、能提交成功。之后问 agent「我选了哪些」→ 它应理解为**你明确一个都不要**，
而不是"你没回答、我来猜"。

> 多选的空集本身就是答案（"这几条轨都要处理吗" → 一条都不要）；单选的"未选"才是没回答。
> 回报措辞也因此分开（`Selected: none — the user deliberately chose none…` vs `No option was selected.`）。

## 3. 只写文本，不选任何选项

在有选项的卡片里**不选任何项**，只在下方文本框写一句「都不对，我想…」，提交。

**期望**：提交成功；agent 明确知道**你没选任何选项**、只给了文本（它不应假称你选了某项）。可以直接问它「我刚才选了哪个选项」来验证——它应回答"没有选，只给了文字说明"。

## 4. 选项 + 补充文本

选一项，**同时**在文本框补一句（例如选「保留原音源」+ 写「但第二段换成另一个」）。

**期望**：两部分都传达给 agent —— 它的后续动作应同时体现"选的那项"与"补充的要求"。

## 5. 开放提问（不给选项）

诱导 agent 问一个没有预设答案的问题（例如让它做一件信息不足、且选项无法穷举的事）。

**期望**：卡片**只有文本框**、没有选项区；文本框的提示文字是「输入你的回答」（有选项时应是「补充说明（可选）」）。

## 6. 空答时提交按钮置灰

卡片刚出现（什么都没选、文本框也空）时看 [提交回答] 按钮。

**期望**：
- 按钮**置灰**（暗底 + 暗字），鼠标移上去**不变亮**、光标也**不是手型**，点它没有任何反应。
- **选中任一选项** → 按钮立刻变为可用（亮蓝）。取消选中且文本仍空 → 又变回置灰。
- **只在文本框打字**（不选任何项）→ 按钮同样变为可用；清空文字 → 变回置灰。

> 置灰而非"能点但没反应"：后者让人以为界面卡了，前者一眼看出"还差点东西"。

## 7. 生成中点停止

卡片挂着时点**停止**键（可以先勾几个选项、打点字，看它们会不会被当成答案）。

**期望**：
- 卡片原地变成只读块，**一个选项都不打勾**、右下角灰字「未回答」（详见 9b）。
- 那一轮结束（末尾灰字「已停止」）。
- **紧接着不重开**，发一条消息问它「刚才那个问题我回答了吗」→ 它应表示**没有拿到结果 / 结果未知**，而不是当作你答了空、也不是当作没问过。

> 原理：取消时 `tcs.TrySetCanceled()`，这次调用因此成为悬空调用、被补一条「结果未知」的合成结果
>（同其它工具，见 `CloseDanglingToolCalls`）。刻意不返回空答案——那会让模型以为你答了个空。

## 8. 切走会话再切回

卡片挂着时切到另一个会话，再切回来。

**期望**：卡片**还在原处等着**（连同已选中的项与已输入的文字），可以继续回答。后台会话里的卡片同理——回答它照样能让那一轮继续跑。

## 9. 重开会话后的留痕（**与刚回答完时长得一模一样**）

回答完一个问题（用例 1 / 用例 4 各测一次），关闭并重开该会话。

**期望**：与实时一样是**工具块 + 只读问答块**两者并存：
- `ask_user_question` 的工具调用块在原位（可展开看参数/结果原文）。
- 其后是只读问答块，**带完整的卡片外框**（圆角/底色/边框，与实时卡片一致——曾漏过整层框）：
  问题、全部选项、你选中的项（打勾+白字，其余压暗）、补充文本都在，与你刚提交完那一刻**看起来完全相同**。

> 反解可靠的前提：回报里选中项是**逐行**列出的（`- 选项`），不是逗号拼接——否则选项名自带逗号就无从拆分。
> 这一点对模型同样重要：拼成一行它也分不清是几项，而且不会报错、只会静默误解。

## 9b. 未回答的留痕（问了但那一轮被打断）

诱导 agent 提问 → **不回答**，直接点停止 → 重开该会话。

**期望**：仍是只读问答块（问题 + 全部选项、**一个都不打勾**），右下角一行灰字「未回答」。
关键是它与"多选时明确一个都不选"要能区分开——后者不会有这行字。

**实时也应如此**：点停止那一刻，卡片就该原地变成这个样子（问题 + 全不勾 + 「未回答」），
而不是保留你当时勾了一半的状态（那些没提交、不是答案，显示出来会误导）。

## 10. 回归：授权卡片（顺带修了同一个顺序 bug）

让 agent 做一次需要授权的写操作（Confirm 档下改工程 / 改设置）。

**期望**：升级卡片照常出现、三个按钮（应用本次/始终允许/拒绝）行为不变；**并且它现在也落在自己那次工具块的下方**
——此前它与问答卡片犯的是同一个错（工具块经 `Progress<AgentEvent>` 异步 Post，而卡片回调在 UI 线程同步执行，
直接建就抢在工具块之前落地），已一并改成排队渲染。

## 判定汇总

| # | 用例 | 结果 |
|---|---|---|
| 1 | 单选圆点、整行可点、互斥、可取消、提交留痕 | |
| 2 | 多选方框、可多选 | |
| 2b | 多选**一个都不选**也能提交（空集是答案） | |
| 3 | 只写文本不选项 → agent 知道你没选 | |
| 4 | 选项 + 补充文本，两者都生效 | |
| 5 | 开放提问只有文本框、提示文字正确 | |
| 6 | 空答时提交按钮置灰，有内容即启用 | |
| 7 | 点停 → 灰字已停止 + 上下文为"结果未知" | |
| 8 | 切走再切回，卡片与已填内容都在 | |
| 9 | 重开会话：工具块 + 只读问答块（**带外框**），与刚答完时一致 | |
| 9b | 未回答的留痕：全不勾 + 灰字「未回答」，实时与重载一致 | |
| 10 | 授权卡片行为不变，且同样落在工具块下方（回归） | |
