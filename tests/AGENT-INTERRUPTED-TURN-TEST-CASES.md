# Agent 中断轮（应用被强杀）测试用例

覆盖新增的**中断态识别 + [继续] 按钮**。此前：生成过程中关掉软件，重开后只剩一条光秃秃的用户消息——
没有任何标记说明"这一轮没等到答复"，也没有出路（[重试] 只在技术失败轮才渲染），用户只能再发一条消息，
而那会让上下文里出现两条连续 user。

同一刀里还改了**轨迹增量落盘**：此前一轮的全部轨迹是在轮末一次性写盘的，中途退出就全丢——
一句话触发的长任务干到一半没了，会话里只剩用户那一句，既看不出它干到哪，续跑时模型也会因看不见自己做过什么而从头再来。
现在 runner 每往轨迹追加一条即**同步**回调落盘（同步是必须的：原有的 `Progress<AgentEvent>` 是异步 Post 到 UI 线程，
而工具在 UI 线程同步执行，进程若在事件排队的间隙里消失，落盘就没发生）。

**判据是推断出来的，不是记录下来的**：进程被强行结束时没有一行收尾代码来得及跑，所以不存在"中断"这个落盘标记。
识别条件 = 该轮锚是常规用户消息 + `Outcome` 为空 + **这一轮没有正常收尾**（末条不是"不带工具调用的 assistant 回复"）。
用户点停或技术失败都会经收尾代码写上 `Outcome`，故不会与中断混淆。

**前置**：代码已构建。会话文件在 `%APPDATA%\TuneLab\AgentSessions\<id>\session.json`。

---

## 1. 基本复现：生成中关掉软件

打开 agent 面板，发一条**会让它跑一会儿**的消息（例如让它连续跑几个脚本，或写一大段文字）。
趁它还在输出时**直接关闭 TuneLab**（关窗口即可，不必用任务管理器）。重开 → 打开该会话。

**期望**：
- 用户消息还在（persist-on-send 本就保证这点）。
- 其后出现**灰字一行**：「这条消息没有等到回复（生成期间应用被关闭了）。」
- 该行右下角有 **[继续]** 按钮。
- **不是红字**、**不带 `Error:` 前缀**——这不是技术失败，没有错误原因可报。

## 2. 点 [继续] 应接着答，而不是让你重说

在用例 1 的状态下点 [继续]。

**期望**：
- 直接开始生成，**不会**在对话里多出一条重复的用户消息（它走 `RetryAsync` = 对当前上下文续跑）。
- 模型的回答**针对那条消息**（说明上下文确实带上了它）。
- 那行灰字提示**就地降级成「…（已继续）」**、[继续] 按钮消失。不能仍是原文——那读起来像"本轮还没完成"，
  而实际上后面已经续跑完了（对照错误条目被重试后加的「（已重试）」）。
- **再次重开该会话**：那行「…（已继续）」**仍在原位**，且该轮显示为正常轮（有回复、有脚注）。

> 为什么重开还必须看得见：中断提示是**推断**出来的（见 `IsTurnComplete`），续跑成功后那一轮就有了正常收尾，
> 推断不再成立、整行会凭空消失，历史里便再无线索说明中间为何断过。所以点 [继续] 时会同时落一条 `notice`
> 记录，落点即当时的中断处，续跑内容排在它之后。这与 `RoleError`「永不删」是同一条理由。

**变体**：点 [继续] 后若续跑**又失败**（例如额度用尽），应看到「…（已继续）」留痕 + 其后的红字 Error + [重试]，
两条痕迹并存、先后正确。

**变体**：中断后**不点** [继续] 而直接发新消息 → 不落 `notice` 记录（那轮确实还没被继续过），提示保持原文；
重开后该轮仍显示中断提示，但**不再有按钮**（不是末轮了）。

## 3. 只有末轮给 [继续]

制造两轮中断：按用例 1 中断一次 → 重开后**不点继续**，直接再发一条新消息 → 趁它生成时再次关掉软件 → 重开。

**期望**：两轮都显示灰字提示（都留痕），但**只有最后一轮**有 [继续] 按钮。

> 为什么：`RetryAsync` 是对**当前上下文**续跑。给非末轮点，结果会落到对话底部、归属错位。
> 与技术失败轮的 [重试] 同一口径。

## 4. 发新消息会收掉 [继续]

在用例 1 的状态下**不点继续**，直接在输入框发一条新消息。

**期望**：新一轮正常开始；上面那个 [继续] 按钮**消失**（末尾已换人，续跑的语义不再成立），
但灰字提示行**仍留着**。

## 5. 正常轮不受影响（回归，**含"不许重复"**）

正常发一条**会调好几次工具**的消息、等它答完，重开会话。

**期望**：显示为正常轮，**没有**灰字提示、**没有** [继续]，脚注（token/calls）照常显示。
**重点**：工具调用与回复**逐条只出现一次**——生成期间已逐条落盘，轮末若再整体补写一遍就会**全部翻倍**
（水位没做对就是这个症状）。有疑问可直接看 `session.json` 里该轮的记录条数。

## 5b. 半轮的工具调用被保留（本刀的核心）

发一条会让 agent **连续调好几次工具**的消息（例如让它逐个跑几个脚本）。等它**至少完成两三次**工具调用后，
关掉软件。重开 → 打开该会话。

**期望**：
- 那几次已完成的调用**完整重放**（工具名、参数、结果都在），不再是只剩用户一句话。
- 若关闭时正卡在某次调用中途，那一次显示为**中止**（既不是成功也不是失败——宿主无从判断它成没成）。
- 灰字提示 + [继续] 照常出现。

## 6. 点停止 / 技术失败不受影响（回归）

- 发一条消息，生成中点**停止**按钮 → 重开会话：应显示灰字「已停止」，**不是**中断提示（结局字段已落盘）；
  已输出的半截文本应在原位（见用例 6c）。
- 制造一次技术失败（例如把模型 API key 改错再发送）→ 重开会话：应显示**红字** `Error: …` + [重试]，
  **不是**中断提示。

## 6b. 中断在工具中途 → 续跑不该重复施加副作用

让 agent 执行一个**有外部副作用**的工具（最好用 `export_project` 导出到某个路径），趁它正在执行时关掉软件。
重开 → 点 [继续]。

**期望**：agent **不会闷头再导一次**。它应当先说明/查证那次调用结果未知，再决定要不要重做。

> 原理：那次调用在历史里是悬空的（发起了、没有结果）。重建上下文时不再把它滤掉，而是补一条
> 「结果未知，运行被中断；它可能已完成、部分完成或根本没跑，重试前请先确认当前状态」的合成结果。
> 滤掉的话模型根本不知道自己调过它，就会直接重调——对导出文件 / 改设置 / 绑快捷键这类**不可撤销**的操作，
> 那就是重复施加。也不能编成"成功"或"失败"：宿主真的无从判断。

## 6c. 点停止 → 半截文本留下来，但**不进上下文**

趁模型正在**流式输出正文**（还没调工具）时点**停止**键。

**期望（实时）**：已输出的那段文字**留在界面上**，末尾灰字「已停止」。

**期望（重开会话）**：那段半截文字**还在原位**——这是本条的重点。此前它只存在于界面上，既不进上下文也不落盘，
重开就凭空消失，只剩你的消息 + 灰字「已停止」（等于告诉你"这儿停过"却不给看停在哪）。

**期望（上下文）**：接着再发一条消息，模型**不该知道**那半截话的内容。可以直接问它「你刚才说了什么」来验证——
它应当表示没有说过 / 不知道，而不是复述那半截内容。

> 语义：那次回复已作废，所以不喂回模型（否则它会把没说完的半截话当成自己的既有表态）；但你要能看见当时说到哪，
> 所以照样落盘。存储上是一条带 `Stopped` 标记的 assistant 记录，UI 照常渲染、`ReconstructHistory` 按标记跳过。
> 技术失败发生在流式途中同理（那条轮还带 [重试]，重试即重新生成这次回复）。

## 6d. 点停落在工具执行中 → 那次调用是「中止」，不是「工具报错」

让 agent 执行一个**耗时可感**的工具（例如 `export_project` 导出，或一个跑得久的脚本），趁它**正在执行**时点停止。

**期望**：那个工具块显示为**中止**（灰/中止态），**不是**红色错误。此前 `OperationCanceledException` 被
"工具异常"那个 catch 一并吞掉，会留下一条 `Error: The operation was canceled.` —— 把你的停止动作记成工具失败。

**顺带验证上下文（不重开）**：紧接着发一条消息问它「刚才那个操作成功了吗」。

**期望**：它应表示**结果未知 / 需要确认**，而不是当作没调过、也不是闷头重做一次。

> 这条同时是"实时与重载一致"的封条：以前实时上下文把悬空调用整段砍掉（模型不知道调过 → 可能重复施加副作用），
> 重开后却补成"结果未知"。现在两条路径共用同一份合成结果，"重开前继续"与"重开后继续"行为一致。

## 6e. 撞失控防护上限（**无法手测，仅记录判据**）

上限是 1000 个工具回合，正常用不可能撞到，故**不要求实测**。此处记录预期行为供代码审查核对：
撞上限时应渲一行中性灰字「Stopped after 1000 tool-call rounds (runaway guard). What's above is what got done.」，
并作为一条 `notice` 记录落盘（重开可见）；该轮仍算**正常轮**（显示脚注、不给 [继续]）；这条提示**不喂模型**。

> 它曾两次"修了但没生效"：先是挂在"连一句话都没产出"的兜底分支上永不执行，后是塞进 `AgentTurnResult.Text`
> 而那个字段既不参与渲染也不落盘。现在走独立的 `StopNotice` → notice 记录。

## 7. 插话后被强杀

发一条消息 → 生成中在输入框再发一条（软插话，会渲染成轮内的小气泡）→ 趁还在生成时关掉软件 → 重开。

**期望**：仍判为中断（插话也是用户在说，不算答复）——显示插话小气泡 + 灰字提示 + [继续]。
