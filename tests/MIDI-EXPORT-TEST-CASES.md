# MIDI 导出测试用例

覆盖新增的 MIDI 导出能力（`MidiUtility.Serialize` + `mid`/`midi` 两个 exporter 注册）。
**只测受影响范围**：导出本身、导出→导入的往返、以及三条调用它的通道（「导出为」菜单 / 另存 / agent `export_project`）。
既有基线测试文档不受影响，无需重跑。

**已由单元测试封条的部分**（`tests/TuneLab.Tests/MidiExportTests.cs`，11 项，跑 `dotnet test` 即验）：
往返保真（音符位置/时长/音高/歌词）、中文 UTF8、tempo map、非 4/4 拍号折算、part 锚点折进绝对 tick、
多 part 合并、裁剪范围外不导出、非正时长剔除、audio part 跳过、空工程、流契约（不 Seek / 不 Dispose 宿主流）。
**下面只列单元测试覆盖不到的**：真实 UI 通道、以及**第三方软件的兼容性**（自家 reader 读自家 writer 是循环论证）。

**前置**：代码已构建（`dotnet build` 0 错误）。UI 里格式的显示名是 **MIDI**。需要重启 TuneLab 才能看到新注册的 exporter。

---

## 1. 「导出为」菜单里出现 MIDI

打开任意工程 → 菜单「导出为」。

**期望**：列表里除 tlp/tlpx 外，**多出 mid 与 midi 两项**（显示名 MIDI）。此前这里只有 tlp/tlpx。

## 2. 基本往返：导出再导入

准备一个工程：至少两条轨、轨名用**中文**、每轨一个 part、part 里几个音符并**逐个填中文歌词**，
再在时间轴上加一个变速点（如第 2 小节转 90 BPM）。

导出为 `a.mid` → 新建空工程 → 导入 `a.mid`。

**期望**：
- 音符的位置 / 时长 / 音高**逐个对上**。
- **中文歌词逐字回来**（这是最容易坏的一环——若显示成乱码或单个怪字符，就是 UTF8 那条路断了）。
- **轨名回来**（原先导入侧读不到轨名，本轮一并修好；若显示成 `MidiTrack_1` 之类的兜底名即为回归）。
- 变速点位置与 BPM 回来。
- **如实丢掉**：音源变回空、自动化曲线/音高偏差/颤音/音素/effect 链全无。这是 MIDI 的固有落差，**不是缺陷**。

## 3. 非 4/4 拍号（回归重点）

工程里设 3/4 起，第 3 小节转 7/8，第 6 小节回 4/4。导出 → 导入。

**期望**：三个拍号的**小节位置与拍号值全部对上**。

> 为什么单列一条：导入侧原先的小节折算是逐级整数除、且拿新拍号去量旧区段，**非 4/4 一律错位**
> （3/4 下 2 小节 = 2880 tick 会被算成第 1 小节）。它只在"拍号从未变过"时恰好正确，所以以前没被发现。

## 4. 裁剪过的 part

把一个 part 的左右边缘各拖进来一些（让它两端各裁掉若干音符），导出 → 导入。

**期望**：**只有可见范围内的音符**被带出来，裁掉的不出现。判据是音符**起点**是否落在可见区间内；
命中的音符**整个**写出、不会被截短。

> 语义选择：MIDI 没有"存在但被裁掉"的概念，若把裁掉的也写出去，往返就等于凭空多出用户已经裁掉的内容。

## 5. 一轨多 part

一条轨上放两个不相邻的 part（如第 1 小节和第 5 小节各一个），导出 → 导入。

**期望**：导回来是**一条轨**，两段音符都在、且**落在原来的绝对时间位置**上（不是被压到一起、也不是拆成两条轨）。

## 6. agent 通道（`export_project`）

让 agent 导出到 `<空文件夹>\a.mid`。

**期望**：成功 + 弹授权卡片（路径任意 → 恒过闸门）；文件能重新导入。
agent 的回报**不应声称**音源/自动化/音素被保留。

> 这条同时是 `tests/AGENT-EXPORT-PROJECT-TEST-CASES.md` **第 2 组用例的替代**——那一组原本验的是
> "如实报不支持"，MIDI 导出实现后期望已反转，该文档已同步更新。

## 7. 外部软件兼容性（**单元测试无法覆盖，务必测一次**）

把导出的 `a.mid` 用**另一个支持 MIDI 的音乐软件**打开（DAW / 记谱软件 / 在线 MIDI 查看器均可）。

**期望**：文件被正常识别（不报"损坏"或"格式错误"），音符落在正确的时间与音高上，速度与拍号正确。

> 为什么必须测：本实现是**手写 SMF 字节**（chunk 头 / 大端长度 / 可变长 delta time / meta 事件），
> 而验证它的 reader 也是我们自己的。自家读自家是循环论证——只有第三方解析器能证明字节布局真的合规。
> 歌词能否显示取决于对方是否支持 lyric meta 事件，**不显示歌词不算失败**；音符时间错乱或读不开才算。

## 8. 空工程 / 无音符工程

对一个全新空工程导出 `.mid`。

**期望**：产出一个**合法文件**（不是 0 字节、不报错），能被重新导入（导入结果为空工程）。
