# 参数面板里的插件画布（设计，待确认）

插件自绘的编辑界面（画布）能出现在钢琴窗下方的参数面板里：每个 note / 音素在自己的时间段上放一块画布，与别的参数面板
同时可见。分两种声明，按"这个字段的界面属于哪里"选一种：

| | `CanvasConfig`（侧栏画布，已有） | `CanvasLaneConfig`（画布 lane，新增） |
|---|---|---|
| 属于哪里 | 侧栏属性面板 | 参数面板 |
| 出现在参数面板 | 用户在侧栏右键钉选后才出现 | **常驻**：哪个 note 声明了它，标签栏就有它，不用钉 |
| 在侧栏 | 有 | 没有（侧栏不显示这个字段） |
| 一块画布对应几个对象 | 侧栏里可能是多选；参数面板里一个 | 永远一个 |
| 时间换算 | 没有 | 一定有（`ITimelineCanvasHost.TimeAxis`，不可空） |
| 典型用途 | 与时间无关、或只按对象内相对位置画的编辑（拉伸曲线、XY 面板） | 必须与时间轴对齐的编辑（如音素混合：曲线 + 符号 + 语言） |

**两种"进参数面板"的性质不同**：钉选（属性 lane、侧栏画布）是**用户偏好**——同一个字段有人爱在侧栏调、有人爱在参数面板调，
宿主替用户记住，插件不参与；画布 lane 常驻参数面板是**插件声明的语义**——这个界面本来就属于时间轴，不该让每个用户各钉一遍。

**为什么分成两种而不是一种画布两处跑**：侧栏可以多选，多个对象没有一个共同的时间段，时间换算在那里怎么给都不对；
而按时间编辑的界面本来就逐个对象进行，没有理由出现在侧栏。分开以后，画布 lane 拿到的永远是"一个对象 + 一条时间轴"，
由类型保证，不用判空；侧栏画布保持现有契约不变。代价：同一个字段只能选一种界面——要侧栏里的完整界面就用侧栏画布
（钉进参数面板后没有精确的时间换算），要与时间严格对齐就用画布 lane（侧栏里没有它，也就没有侧栏的多选批量操作）。

前置：参数面板多开（`docs/parameter-panels.md`）；属性 lane 按各 note 自己的声明取形状（`NoteDeclarationCache`）。

## 1. 用户看到什么

| 项 | 规则 |
|---|---|
| 标签栏 | 画布 lane：哪个 note 的声明里有它，标签栏就有它（各 note 声明的并集，同属性 lane 的口径），与属性 lane 同列。侧栏画布：钉了才有 |
| 钉选侧栏画布 | 侧栏里画布字段的右键菜单「在参数栏编辑 / 从参数栏移除」，与属性 lane 同一个入口、同一份钉选存储（`ParameterPinning`）。任何侧栏画布都能钉：宿主不判断它适不适合放在时间轴上，钉了不好用用户解钉即可 |
| 面板里 | 这个参数激活时，视口内每个声明了该字段的 note（note 级字段）/ 音素（音素级字段）各有一块画布：横向占满它的时间段，纵向占满面板高度。没声明的对象那一段是空的 |
| 编辑 | 交互、草稿、提交、弹出与侧栏画布相同（`ICanvasHost` 的契约不变）；提交是一个撤销步。每块画布各管各的：一次拖动不跨到相邻对象的画布 |
| 作为背景参数 | 可见但非激活时照常显示，与其它背景参数同一个画法：先画各背景参数（画布照常调插件的 `Render`、原样画），再整层叠一块半透明黑底，最后画激活参数——背景画布自然被压暗、不接收任何输入。不告诉插件"你此刻是背景"（尽量不扩 SDK 面），插件照常画。**激活参数也是画布时，背景画布不画**、小眼睛也不点亮（两块界面叠起来哪层都看不清）；背景曲线照常画。**画布的可见互斥**：一块面板里至多一个画布可见，打开一个就关掉别的（激活也算打开，所以切回普通参数后作背景的是最近用过的那个）|

## 2. 每个对象一块、各按自己的声明

- 画布的值在**声明时**由插件取出、被创建 control 的工厂捕获，宿主不把值读回给控件。所以每一块都要拿**这个对象自己的那份
  声明**（context 里只有这一个 note），从中按 key 找到这个字段，再调它的工厂。这与侧栏单选是同一份声明，走 part 上的
  按 note 缓存（`IMidiPart.GetNotePropertyConfig(note)` / `GetPhonemePropertyConfigs(note)`，音素按 slot）。
- 只为**视口内**的对象建实例，滚出视口的作废。
- 实例的作废照现有契约：工程里的值一变实例就作废、按新声明重建；插件宣告编辑中（`BeginEdit`）/ 有草稿 / 弹出期间不换实例。
  声明缓存按 part 整体失效（声明 context 经 `Part` 读得到整个 part），故**任何数据变化落定后都会让视口内的实例重建**（编辑落定才作废：
  拖动途中不逐帧重问，松手提交后一次）——
  工厂本就要求廉价，临时状态本就要求能从值与事件位置重算。
- 不限于顶层键：属性树里任何位置的画布都能进参数面板，按路径各成一条 lane（§9）。

## 3. SDK 新增（纯加法，画布尚未发布）

```csharp
// 画布 lane：只在参数面板里、按对象的时间段摆放的值字段。与 CanvasConfig 同一套值语义（没有默认值、恢复默认 = 删掉存值，
// preset、撤销照常；值的形状由插件定、读取时自行校验），可以在 note / 音素属性声明的任何位置（§9）。侧栏在它的位置显示摘要 + 编辑按钮（§9.4）。
// 构造函数全封，只走静态工厂 + With（同 CanvasConfig）。
public sealed class CanvasLaneConfig : IControllerConfig
{
    public Func<ITimelineCanvasHost, ICanvasControl> CreateControl { get; }
    // 标签栏按钮与焦点圆点的颜色（hex）。与 AutomationConfig.Color 同一约定：默认透明（"#00000000"）= 不指定，
    // 宿主从调色板分配（确定性：按声明顺序、避开已占用色）；想定颜色就 WithColor。
    public string Color { get; }
    public static CanvasLaneConfig Create(Func<ITimelineCanvasHost, ICanvasControl> createControl);
    public CanvasLaneConfig WithColor(string color);
}

// 画布 lane 的宿主：在 ICanvasHost 之上多一条时间轴（一定有）。
public interface ITimelineCanvasHost : ICanvasHost
{
    ICanvasTimeAxis TimeAxis { get; }
}

// ICanvasHost 新增（两种画布都有）：
//   画布区域里此刻露在外面的部分（画布坐标的矩形）。侧栏里多因面板滚动露出一部分高度，参数面板里多因时间轴滚动露出一部分宽度。
//   只是提示：不处理它照样正确（整块都画，宿主裁掉看不见的部分）；逐像素采样、自己生成位图的插件按它只算露出来的部分。
//   变化时（滚动、缩放）宿主重新调 Render。
//   Rect VisibleBounds { get; }

public interface ICanvasTimeAxis
{
    // 秒（全局秒，与声明视图 IVoiceSynthesisNoteView.StartTime 同一口径）↔ 画布内横坐标（逻辑像素）。
    // 跟着钢琴窗的 tick 轴，速度变化处不均匀；插件不该假设它线性（以后钢琴窗若能切成均匀时间轴，这里随之均匀，接口不变）。
    // 这块画布覆盖的时间段就是 XToTime(0) 到 XToTime(Width)，不另给起止：它未必等于对象自己的起止
    //（note 级画布用 lane 段，会被钳到下一个 note 的起点；音素的显示时间由宿主排版），插件按自己数据里的绝对时间换算即可。
    double TimeToX(double time);
    double XToTime(double x);
}
```

- 名字：声明叫 `CanvasLaneConfig`——参数面板里一个声明对应一条 lane（lane 身份 = 字段路径，§9），每个对象在这条 lane 上占一块，
  范围严格限在对象那一段。`TimelineCanvasConfig` 这个名字留给将来定义域是整条时间轴的 part 级画布（§10）。宿主接口
  `ITimelineCanvasHost` 不改名、两级共用（都是"多一条时间轴的画布宿主"）；time axis = 秒 / tick ↔ 横坐标换算。
  用户界面上两者都只叫「画布」。
- 没有首选尺寸：宽由对象的时长决定；高是用户的面板布局（各面板高度由用户调、彼此独立），切到这个参数时不随插件变。
  插件按实际尺寸响应排版。
- 控件接口 `ICanvasControl`、绘图接口、事件、草稿 / 提交、弹出、弹窗服务全部与侧栏画布共用。
- 侧栏画布钉进参数面板时，host 仍是 `ICanvasHost`（没有时间轴），插件只拿到这一块的宽高，按相对位置画；对插件零改动。
- 不告诉插件"你在哪"：插件要的是"时间怎么落到横轴上"（`TimeAxis`）与"地方多大"（`Width` / `Height`），两者在任何新位置上
  都成立；位置枚举每加一个值老插件就得重新适配。窄、矮时画紧凑版（如只画曲线和一行符号、点字才弹 `PopupTextBox`），
  按尺寸响应。

### 3.1 `ITimelineCanvasHost`：继承来的成员在参数面板里的含义

`ITimelineCanvasHost` 只比 `ICanvasHost` 多一条 `TimeAxis`；其余成员照搬侧栏画布的契约，下表只列在参数面板里**含义具体化或不同**的地方。
钉进参数面板的侧栏画布（host 仍是 `ICanvasHost`）同样按这张表。

| 成员 | 在参数面板里 |
|---|---|
| `Width` / `Height` | 这个对象时间段的像素宽 / 面板高度。缩放、改面板高度、未钉住的音素在合成后变长变短时变化，宿主重新调 `Render`；滚动不改它们（画布整块跟着平移） |
| `TimeAxis` | 缩放、速度表改动时换算随之变，宿主重新调 `Render`；不因此换实例 |
| `DevicePixelRatio` / `Invalidate` | 同侧栏 |
| `VisibleBounds` | 时间轴滚动、缩放时变（多为宽度上露出一部分），宿主重新调 `Render` |
| 很窄的对象 | 宿主不设下限，照常建实例、交给插件（多窄还能用插件最清楚：一条曲线几像素宽照样看得清）；只有不足 1 像素宽时跳过 |
| `BeginEdit` / `EndEdit`、草稿、弹出期间 | 同侧栏的"面板仍在使用"：本实例不被换掉。参数面板里还额外意味着：滚出视口、别处数据变化（声明缓存整体失效）都**不**作废它，直到编辑结束 |
| `SetValue` / `CommitValue` / `DiscardValue` | 目标永远是这一个对象（不会有多选，也就不会有 Multiple）。提交是一个撤销步；音素级字段提交时先 `LockPhonemes` 再写值，同一步 |
| 实例作废的时机 | **看不见不等于失效**。只在真正失效时作废：外部改了本字段的值、撤销、part 里任何数据变化落定（声明缓存整体失效后按新声明重建；拖动途中不作废，松手提交后一次）、切换 part、对象被删除、工程关闭。滚出视口、切走参数、面板关闭 / 收起 / 整区隐藏时实例只是不显示、不收事件，回来时直接复用（补发 `Enter` 后 `Render`），保留数量不设上限。以上都受上一行的编辑保护 |
| 鼠标 | 坐标是这一块画布内的真实像素。按下后照旧捕获：拖出这一块继续由本实例收到移动与抬起，**不会**交给相邻对象的画布 |
| `OnScroll` 未置 `Handled` | 交给参数面板自己的滚轮处理（横向滚动 / 缩放时间轴），而不是"滚动所在面板" |
| 键盘 | 同侧栏：点一下获得焦点；没置 `Handled` 的键冒泡给编辑器快捷键（空格播放、撤销等） |
| `Enter` / `Leave` | 同侧栏的成对保证；画布因滚动、缩放移到静止的指针下面时，宿主同样主动补发 `Enter` |
| `PopupTextBox` / `PopupMenu` | 矩形仍是画布坐标；可以超出这一块画布（音素常常很窄），按现有"太小时扩到一行高与最小宽度、超出屏幕挪进来"的规则 |
| `DialogService` | 以主窗口为父窗口，其余同侧栏 |
| 底色 | **透明**，与自动化参数一致（不画侧栏那种深色圆角底） |

## 4. 坐标：真实像素，宿主不做映射

- 绘制与指针坐标都是画布内的真实逻辑像素：插件画在哪、画多大，屏幕上就是哪、就是多大。弹出框的矩形同理。
- 宿主**不**替插件把横轴按速度变形。变形需要猜每个图元是"时间范围"还是"固定大小的标记"，猜错了插件没有退路；
  换算交给插件，错了是插件自己能改的代码。
- 代价：所见即所闻归插件负责。按秒画的曲线若只换算控制点再连直线，跨过速度变化处会与听到的不一致；逐像素采样
  （每一列 `XToTime(x)` 换回秒、再按秒求值）就与合成严格一致。不提供"按秒折线 → 屏幕折线"的帮手：逐像素采样已经精确，
  帮手只省点数；真有插件需要再加（`ICanvasTimeAxis` 由宿主实现，加成员是纯加法）。

## 5. 几何与长度变化

- 一块画布的横向范围：note 级 = 该 note 的 lane 段（与属性 lane 同一套去重叠，`NoteLaneRanges`）；
  音素级 = 该音素的显示几何（`note.DisplayPhonemes`）。纵向 = 参数面板高度。**不留缝**（数值 lane 的 1px 缝不照搬）：画布正好覆盖时间段，`XToTime(0)` / `XToTime(Width)` 就是起止，分隔由插件自己画。
- 缩放、滚动、改面板高度、未钉住的音素在合成后变长变短，都只是 `Width` / `Height` / `TimeAxis` 变了，宿主重新调 `Render`。
- 音素级画布的提交走属性 lane 的写回范式：先 `LockPhonemes`（合成音素 → 钉死，保几何），再写属性，同一个撤销步。
  草稿不是工程数据，不触发合成，所以编辑过程中几何不会因为自己的草稿而变。

## 6. 存储与路由（宿主内部）

- 值照常存在 note / 音素的 `Properties` 里，按 key 存取（与属性 lane 相同）。
- 参数面板里的路由沿用属性 lane 的 `NoteLane` / `PhonemeLane` 来源：画布 lane 与钉了的侧栏画布都并入 lane 集合
  （`NoteLaneConfigs` / `PhonemeLaneConfigs` 按条目区分是数值 lane 还是画布），面板布局持久化（`ParameterRefInfo`）不变。
- 常驻的画布 lane 没有钉选记录，轨色取 `CanvasLaneConfig.Color`；未指定（alpha 为 0）时宿主分配。分配在宿主物化声明的入口
  统一做（同自动化参数），下游永远看不到透明色。

## 7. 插件须知（写进插件文档）

1. 画布要能接受任意宽高：参数面板里宽度是对象的时长、高度是面板高度，可能很窄、很矮、也可能很宽。按尺寸响应排版。
   放大后 `Width` 可能上万像素：逐像素采样、自己生成位图的，只算 `VisibleBounds` 露出来的部分。
2. 画布 lane 里按秒画的内容用 `TimeAxis` 换算；曲线逐像素采样，别只换算控制点再连直线。数据按"这块画布内的相对位置"
   定义的，时间段取 `XToTime(0)` 到 `XToTime(Width)`。
3. **画布里以宿主的换算为准**，不要用插件自己合成时算出的音素时间来画：宿主给的是屏幕上显示的时间段（`DisplayPhonemes`），
   画布要与用户看到的音素块对齐。两者在合成结果回填后一致（未钉住的音素显示的就是引擎的结果，钉住的两边用同一个
   `PhonemeLayout`），只在改动后、合成回来前的过渡期不同；显示一更新宿主就重新 `Render`。
4. 插件自己的默认值（没设过时读值补的那个）宜**中性**（未调即无效果），或只按对象内的相对位置定义：未钉住的音素长度随合成变化，若默认值的作用依赖长度，
   用户没碰过的对象会在别处编辑后听感改变。
5. 选哪种：界面属于侧栏、与时间无关 → `CanvasConfig`；必须与时间轴对齐、逐个对象编辑 → `CanvasLaneConfig`。
   同一个字段只能选一种。
6. **存储坐标决定对象被拉伸时的行为**，宿主不替插件处理：按比例（0..1）存 → 随对象等比伸缩（形状类：力度、颤音包络）；按距起点的
   偏移存 → 头固定、尾部延长或截断（起音类）；按距终点的偏移存 → 释音类；也可以分段混合。要有意识地选，并配合第 4 条的中性默认值。

**音符级自动化轨（宿主绘制）暂不做**：逐音符的随时间变化内容，画布 lane 已能覆盖（插件按第 6 条自选存储坐标）。宿主绘制版的独有价值是
宿主与 agent 看得懂这些点；等真有"agent 要编辑逐音符包络"这类需求再做。届时拉伸行为是参数自身的语义、宿主猜不了，由声明**必填**
（如 `Proportional` / `FromStart` / `FromEnd`，混合以后再加），另需定：音符拆分 / 合并时曲线怎么切接、与 part 级同名参数谁覆盖谁、
参数面板复用钉选音符属性的逐音符分段显示。这不是"note 层缺一类"的不对称：note 只有属性一列（画布 lane 即属性），part 多出的是
"轨"一列（自动化轨 / 将来的画布轨），音符本就不承载轨。

| 出现过之后 | **已定：声明暂时问不到时保留，问到没有就去掉**（按 part 记，音源一换清空记录）。音素声明要等引擎对音素表态：还有 note 没表态（全部标脏、合成回来前）时，出现过的音素级画布标签留在原位、颜色不变，面板里只是空的——标签栏跟着声明一会儿有一会儿没有观感很差。note 声明随时同步问得到，没有"暂时不知道"：没人声明就去掉。曾定为"出现过就一直在"，数组 / 列表进来后推翻：列表长度是用户在增删，删掉的元素标签会越积越多。重新出现时颜色沿用上次的 |
| 标签栏要对全部 note 求并集 | 标签栏不看视口（滚动不会让标签出现 / 消失），但常驻画布没有钉选可短路：每次数据提交后都要把所有 note 问一遍（实测 300 note 约 3ms，几千 note 几十 ms）。先接受；成问题时再让插件在 part 级声明里预告会声明哪些画布 lane，没预告就不扫 |
| 跨对象连续 | 不做：每个对象一块独立画布，跨音符的曲线画不出连续感 |
| 禁止钉选侧栏画布 | 不做；真有需求再给 `CanvasConfig` 加一个 With（纯加法） |

## 9. 嵌套位置：按路径的 lane（已实现）

画布 lane 是属性树的一员，只是编辑界面在参数面板里；它可以出现在声明树的任何位置——对象（`ObjectConfig`）的成员、
定长数组（`ArrayConfig`）与列表（`ListConfig`）的元素、键控容器（`ExtensibleObjectConfig`）的条目里，任意嵌套。
用户钉选的字段（有界数值、侧栏画布）同样可以钉任意位置的节点。

### 9.1 lane 的身份 = 路径

- 路径逐段：对象成员 / 键控条目 = 键，数组 / 列表元素 = 下标。编码成一个字符串作 lane id（段间 `/`，段内的 `~`、`/`
  转义成 `~0`、`~1`）。顶层字段的路径就是它的 id 本身——既有的钉选、工程里存的面板布局原样认得。
- lane 集合 = 各 note 声明里出现过的路径的并集（同 §1）：某个 note 的数组只有 2 个元素，它在第 3 条 lane 上就没有块。
- 列表下标的含义随用户增删、调序而变（删了第 1 项，后面的往前挪）：值跟着元素走，所以数据不会错位；lane 按下标排，
  同一条 lane 在不同 note 上装的是哪一项由用户自己的编辑决定。这是有意接受的——画布是属性树的一员，树怎么编由用户。

### 9.2 标签名：最短不重名

- 默认只显示**末段的显示名 + 路径上的序号**：元素本身就是画布时 = 容器名 + 序号（「音素混合 2」）；画布是元素对象里的成员时
  = 成员名 + 序号（「曲线 2」）；路径上有多层数组 / 列表时序号依次排开（「曲线 2-3」）。序号从 1 数。
- 与标签栏里别的标签**重名时才往前补一层**祖先的显示名，补到不重名为止，补出来的那段带回自己的序号（「音素混合 2 · 曲线」与「表情 2 · 曲线」：2 是音素混合的第 2 项）；没补出来的祖先段的序号并到第一段显示的段上。
  重名按标签栏此刻实际出现的标签判断，lane 增减时个别标签可能变长 / 变短。
- 悬停显示完整路径。顶层字段不变，仍是字段名本身。
- 插件须知：叶子节点（画布字段）的显示名尽量别重名，标签就能一直保持最短。

### 9.3 读写

- 读：沿路径从 note（音素级：该位音素）的属性里取；路径上缺的节点 = 默认值（同侧栏数组的懒视图：读不创建）。
- 写：沿路径写到那一个节点；路径上缺的数组 / 列表元素先按元素默认值补齐、首次写入时整段落地（复用侧栏数组的懒补齐）。
  音素级先固定音素。同一个撤销步。

### 9.4 侧栏：摘要 + 编辑按钮

每个画布 lane 所在的位置（含顶层、各数组 / 列表元素里）在侧栏占一行：字段名、摘要、最右一个编辑按钮——点了在焦点面板里
激活这条 lane（参数区藏着就先显示出来）。列表照常增删、调序；元素里的其它普通字段照常显示、照常多选批量编辑。
摘要由插件在声明时按当时的值算好（多选写什么也由插件定），没给时宿主兜底「默认 / 已修改 / 多值」。

**SDK 新增**（纯加法，画布未发布）：`CanvasLaneConfig.WithSummary(string)` 与 `Summary`，与 `CanvasConfig` 同名同义。

### 9.5 推翻的旧口径

- 「只认顶层键」（§2、属性 lane、插件文档 §10.6 里「多层数据只能拆成多个顶层键」那句）——实现时一并改掉。
- 「侧栏不显示画布 lane」——改为显示摘要行（不在侧栏里编辑）。

## 10. part 级时间轴画布 `TimelineCanvasConfig`（暂不做，等真插件有需求再定点做）

**现状（已实现）**：画布 lane 只在 note / 音素属性声明里有效。放在别处——part 属性、效果器属性、扩展设置窗、输入表单
（脚本工具与插件按钮弹出的那种）——侧栏那一行显示「此处不支持该画布」，不显示摘要也不给按钮，并记一条警告点名字段路径
（同一路径只记一次）。判据是这块面板有没有接「去参数面板编辑」的钩子（`FieldHooks.EditCanvasLane`）：没接 = 这里没有时间轴。
扩展设置窗与输入表单永远不支持。

将来做了 part 级的新声明族（`TimelineCanvasConfig`）后，part / 效果器上用新类型，不把 `CanvasLaneConfig` 放进去——所以上面这几处
会一直是「此处不支持」。

### 10.1 定论：part 级与 note / 音素级本质不同，将来另起一个声明族

现在没有真插件要 part 级，做了也没法真实测试，所以不做；但定下了它将来的形态。讨论中先试过把 `CanvasLaneConfig` 放进 part 属性，
标脏、通知身份、存储样样别扭——根子在于硬把一条轨塞进属性树。两者按本质分开，宿主本来就按这条线分了两类：

| | note / 音素级画布 lane `CanvasLaneConfig`（现在这套） | part 级时间轴画布 `TimelineCanvasConfig`（将来） |
|---|---|---|
| 是什么 | 对象的一个属性 | 一条贯穿时间的轨 |
| 宿主里的同类 | note / 音素属性 | 自动化轨 |
| 定义域 / 绘制范围 | 严格限在对象自己那一段（note 段钳到下一个 note 起点、音素按排版），范围外不画——相邻对象各占一段 | 整条实数轴（局部 tick 可负、可超出 part），与自动化轨一样；part 裁剪外照画，由宿主盖遮罩（同音符），插件对裁剪无感 |
| 跟着对象走 | 是：移动、复制、粘贴音符、预设都带着它 | 第一版不跟（宿主不知道画布里放了什么）；有了 `GetRange` / `SetRange`（§10.2）后可以跟 |
| 标脏 | 整个对象重合成可以接受（音符本来就短） | 必须知道改了哪几段 |
| 身份 | 按路径定位、可嵌套（§9），会话不需要区分 | 需要像 `ISynthesisAutomation` 那样的代理对象让会话订阅 |

- **note / 音素级：维持现状**，仍是 `IValueConfig`、在属性树里任意位置（§9）。
- **part 级：将来另起一个与 `AutomationConfig` 平级的声明族**（同一个声明入口里，声源与效果器都有），不是 `IValueConfig`、
  塞不进 `ObjectConfig`：id 平铺、有自己的存储（整块存、撤销只换引用，见 §11）、会话拿到 id → 代理对象的表（值 + 带区间的变化通知），
  "订阅了谁就知道是谁"，通知身份的问题自然消失。
- **命名（已定）**：part 级叫 **`TimelineCanvasConfig`**——它的定义域就是整条时间轴，名字字面即事实。不用 `Automation`
  （会把它收窄成参数曲线，实际可放任何时间轴相关的东西：区段、视频帧、歌词块……）。现在的 note / 音素级在画布发布前已改名为
  `CanvasLaneConfig`（原名 `TimelineCanvasConfig` 只说对了"画在时间轴上"一半，"依附对象、严格限在对象那一段"没体现）。
  插件文档讲清怎么选：这是某个音符 / 音素的属性 → `CanvasLaneConfig`；这是一条贯穿整个 part 的轨 → `TimelineCanvasConfig`。
- **`Width` 对 part 级没有意义**（实数轴给不出宽度）：填钢琴窗可滚动总宽、仅供参考；绘制以 `VisibleBounds` 与时间轴换算为准。
  part 裁剪外**可以编辑**，与自动化轨一致；出不出声画布不用操心——part 本来只有裁剪范围内会在音频引擎里出声，合成取下一分片也按
  裁剪范围取。

### 10.2 届时要接着定的（讨论过的要点，别从头推导）

- **标脏**：画布在**提交**时报改动范围（不是草稿阶段：会把拖动途中经过、最终没变的地方也算进去），可以报多段；不报 = 整段。
  宿主当中介：声源经代理对象的区间通知交给会话，效果器由宿主按区间相交标脏。否决了插件比对新旧值（数据大、形态不定）和画布与会话私下沟通
  （效果器插不进手、跨线程配对、撤销与预设等写入拿不到范围）。
- **宿主自己发起的写入**（预设、恢复默认、agent 写值）与撤销 / 重做：按整段通知，或把提交时的范围随撤销记录存下复用。
- **改动说明**：要区分"改了画布里哪一样东西"时，再给改动记录加插件自定的说明，用 `PropertyValue` 不用 `object`（对纯数据自由度一样；
  合成侧数据一律可序列化、为跨进程留路），且须描述"哪里变了"而非"做了什么操作"（撤销时同一条记录原样重发）；Null = 不知道改了什么。
  效果器若要收到这份说明，得另开一条通知。第一版可以只有时间段，结构体保证以后加字段是纯加法。
- **范围的单位**：画布关心 tick——提交时插件按局部 tick 报；宿主换成全局秒，经代理对象的 `RangeModified` 报给关心秒的合成侧。
  多段 = 每段触发一次（与 `ISynthesisAutomation` 同一签名），不另造改动记录类型；将来要附"改了什么"的说明再另开一条通知。
- **时间坐标**：tick 一律相对 part，存储、交互都是，与自动化轨、音符一样（见 §12）。值宿主不解读、挪不动，所以宿主随值另存一个
  偏移（平时 0）：拆分 / 合并后 part 锚点变了，自动化轨与音符是宿主逐点改写坐标，画布值改写不了，就只记下偏移，换算时算进去，
  插件无感。挪动 part = 什么都不用改；
  **拆分** = 左右两半各拿一份完整的值、原点不变，各显示自己那段（数据冗余；再拉长 part 会露出原先看不见的部分，可接受）；
  **选区粘贴**进一个已有该画布值的 part：两块整值合不了 ⇒ 粘贴时跳过画布（与"不跟着音符搬"同理）。
- **区间读写 `GetRange` / `SetRange`（以后加，第一版不做）**：声明上用 `.WithGetRange(...)` / `.WithSetRange(...)` 挂两个插件函数：
  ```csharp
  GetRange(value, start, end)         → 片段   // 读出这个区间（局部 tick）的内容，原值不变
  SetRange(target, start, end, piece) → 新值   // 用片段覆盖目标的这个区间（不插入、不挪动后面的内容）；另附片段来源的引擎 / 声源
  ```
  语义同 .NET 的 `List<T>.GetRange` / `ArrayList.SetRange`。按事实命名（读写某个区间），不按用途（复制 / 粘贴只是用途之一），
  四个场景都是它俩的组合：拆分 = `GetRange`；合并 = 造空母体后逐段 `SetRange`；粘贴 = `SetRange`；跟着音符搬（见下）= 原处 `GetRange`
  后把原处设成"没设过"、再 `SetRange` 到新处。宿主内部的 `RangeInfo` / `PasteAt` 是宿主自己的用途命名，不进 SDK。
  **画布没有默认值**（§13）：没设过 = Null，两个函数都要接受 Null（作目标 = 整条都没设过，作片段 = 这一段没设过）。
  **删除一段 = `SetRange(target, s, e, Null)`**：把这一段设成"没设过"，在自己的格式里怎么表达由插件定（如留空隙、读时按自己当前的默认值
  补）——所以删掉的部分永远跟着插件此刻的默认值走，不存在"按哪个默认值写回去"的问题。不另加 `ResetRange`。
  声明是 SDK 封闭族、走既有 `With`，纯加法、无需默认体。**兼容靠"没提供 = 第一版行为"**：拆分各拿整值、粘贴跳过、合并取母体整值——
  第一版就按这套实现，老插件以后行为不变。两者须是纯函数（宿主会在撤销、预设、agent 写值等任意时刻调）；抛异常 = 宿主捕获、记警告、当没收。
- **跟着音符搬：第一版不做，有了 `GetRange` / `SetRange` 后可以做**（§10.1 表里的"不跟"指的是没有这两个函数时宿主无从下手）。
- **不按引擎拦截**：截出的数据一律交给插件，附上来源，由插件决定收不收（不收就原样返回目标）。宿主按引擎一刀切会挡掉合理的跨引擎
  情形（插件改过引擎 id 的新旧版本、同作者几个引擎共用格式）；唯一的风险"误收"（别家同 id、碰巧同形状的值）由来源信息让插件自防。
  与换声源一致——换声源时画布值按 id 保留，新声源读到的本来就可能是别家写的（§7：读取一律校验）。
- **合并（逐 id）**：以按时间顺序第一个有该 id 的段为**母体**，用**母体所在段的声源的声明**——从 Null（没设过，原点 = 合并后
  part 的原点）起，再逐段（母体自己也一样）`GetRange` 它的贡献区间、`SetRange` 贴进去；没有该 id 的段跳过。各段都先截取，part 可见区间外藏着的旧内容
  就不会露进结果（与自动化轨合并按贡献区间裁剪同理）。母体所在段的声源也没声明它（本来就是孤儿数据）⇒ 整块保留母体、丢后面各段。
  第一版没有这两个函数 ⇒ 一律整块保留母体、丢后面各段。
- **孤儿数据**：part 上的画布表与自动化轨一样不看当前声源的声明（声明只决定显示与会话拿不拿得到代理），没被声明的 id 原样存着、
  写进工程、不显示、不参与合成；换到声明了它的声源时重新出现，位置因偏移随值存而正确。
- **声明入口**：照 `GetAutomationConfigs` 平行开一个，声源 / 乐器 / 效果器三类引擎都有（效果器有自动化轨，声源怎么接它就怎么接）：
  ```csharp
  IReadOnlyOrderedMap<PropertyKey, TimelineCanvasConfig> GetTimelineCanvasConfigs(<与 GetAutomationConfigs 同一个 context>) => 空表;
  ```
  引擎是插件实现面 ⇒ 带默认体。context 与询问时机都与 `GetAutomationConfigs` 相同；有序表的顺序 = 标签栏顺序。
- **id**：与自动化轨**不强制不重名**——两族存储本来是分开的表（part 上、合成上下文、工程格式各一张）。实现要求是宿主里按 id 定位的地方
  一律按「类别 + id」：标签栏隐藏记录、lane、各面板可见开关走 `AutomationKey`，它已有 source / effect / note / phoneme 的来源维度
  （同 `NoteLane(id)` 与声源自动化轨分开），画布轨再加一种来源；agent / 命令的取值写法加前缀（如 `sourceCanvas:id`，届时定）。
  插件给两族起同一个显示名会出现两个同名页签，属插件自己的选择。
- **会话代理**：与 `ISynthesisAutomation` 同级，合成上下文上与 `Automations` 并列一张 `TimelineCanvases` 表（声源、乐器、效果器的上下文都有）：
  ```csharp
  public interface ISynthesisTimelineCanvas            // 宿主实现
  {
      PropertyValue Value { get; }
      ITempoMap TempoMap { get; }                      // 局部 tick ↔ 全局秒；会话内不变（速度改动走会话重建）
      IActionEvent<double, double> RangeModified { get; }   // 全局秒，同 ISynthesisAutomation
  }
  ```
  `Value` 用普通 getter、不用可通知属性：变化通知必须带区间，`Modified` 不带参数，两个都给就重复（同自动化轨只有求值、没有 `Modified`）。
  合成快照里对应一个只读快照类型，与 `SynthesisAutomationSnapshot` 同级。效果器照旧由宿主按区间相交标脏。
- **界面**：标签栏按对象分组，跟在所属对象（声源 / 各效果器）的自动化轨后面；支持 `WithShownByDefault`（与自动化轨一致）；
  part 属性面板里**不**放摘要那一行（自动化轨在那里是默认值滑条，画布内容宿主不知道，没有可摘要的东西）。
- **agent 读写**：与其他画布类型一样可以读写值：值对宿主不透明，agent 先读插件文档弄清字段怎么拼、表示什么，再自己造数据。
  agent 写入属宿主发起的写入（按整段标脏）；给 agent 的说明里要写明值里的 tick 相对 part。
- **工程格式 SDK**：`MidiPartInfo` / `EffectInfo` 加一张表存「偏移 + 值」（DTO 加字段，纯加法）；格式插件不认识它，导出到别的格式会丢，文档写明。
- **part 预设**：带「偏移 + 值」；tick 相对 part，套到别处不会错位。
- **存储**：按 §11 整块存（基准已测，现存法在大值上不可用）。
- **还没定**：钢琴窗选区删除时画布怎么处理（第一版跳过，有了 `GetRange` / `SetRange` 按上面的"删除一段"处理）。
- **钉进钢琴窗**（不另起"钢琴窗级画布"，就是 part 级时间轴画布换个显示位置）：横向同音符区，纵向由用户在钉的时候选——
  **铺满**（整个音符区，底部半透明的波形 / 参数面板叠在上面）或 **不被遮挡**（只占露出来的部分，上沿以下到当前底部最上一层的
  顶边：波形显示时到波形顶、隐藏时到参数面板顶，随显隐与高度变化）。画布没有首选尺寸，选中的范围就是宿主给的画布区域，插件只按它画、
  不关心宿主布局（频谱类贴底边画，立绘类按高度铺）。音高轴在两种范围下都与琴键对齐（顶边都在音符区顶边）。作背景时画在网格之后、
  音符之前（同立绘）。**待设计的界面**：钉的入口直接给出两种范围（默认值由交互消掉）、钉上后可切换；前景模式怎么进入（同颤音工具的
  层级，但不挤进工具栏）。
- **动态背景 / 动态立绘**：由钉进钢琴窗的画布承担（它有播放状态、自己的合成结果等全部上下文）。立绘接口不升级；纯循环动画用动图已支持。
  以后若真要"插件驱动帧"的立绘，形态是帧来源 + 帧变化通知、宿主只重画，不经宿主给任何合成上下文。

## 11. 存储：画布的值整块存（基准已测，值得做）

现在写一个对象 / 数组值，宿主会把它拆成一棵可撤销、可通知的数据节点树（`PropertySlot.Canonicalize`），每次提交新建整棵树，
每次读又拼回一份整值，撤销历史里留着每个版本的整棵树。值大（长音符上的密曲线）时这三样都会重；part / note 声明在 part 里任何数据提交后都会重问，即使没碰画布也要把值读一遍。

画布的值是整值语义（宿主不解读、不按键通知、多选按整值比较），拆成节点树没有用处。候选做法：画布字段的值**整块存一个不可变的值**，
提交 = 存引用，撤销 = 换引用，读取 = 直接给出；插件构造新值时复用没改的部分，新旧版本大部分共享，撤销历史近似只涨改动量。
工程文件写出的内容不变（老工程读进来仍是节点树，第一次编辑后换成整块，读出来的值相同）。宿主内部改动，SDK 不变，所有画布都受益。
存储层不知道哪个字段是画布，所以要由知道 config 的写入方（画布提交、恢复默认、预设、agent 写值）走一个「整块写」的入口；
漏走的退回节点树，功能正确只是慢。

**基准（2026-11-02，Release，单独的 `DataPropertyObject`，未含撤销记录与通知的额外开销）**：值 = `{ "curve": [[t, v], …], "lang": … }`

| 点数 | 现存法：每次提交 | 现存法：每次读取 | 现存法：每个版本的节点树 | 整块存：提交 / 读取 | 值本身 |
|---|---|---|---|---|---|
| 1 000 | 5.2 ms | 0.26 ms | 约 1.9 MB | 约 0 | 约 0.11 MB |
| 10 000 | 119 ms | 7.2 ms | 约 19 MB | 约 0 | 约 1.1 MB |
| 100 000 | 1.76 s | 125 ms | 约 191 MB | 约 0 | 约 11 MB |

- 一万点曲线每次松手提交卡一百多毫秒；节点树是值本身的约 17 倍，撤销历史每多一步就多一棵——编辑一百次就是近 2 GB。
- 读取 7 ms 看着不大，但声明在 part 里任何提交后都会重问、每次都要读一遍，多块画布叠起来就明显。
- 整块存把三样都降到可忽略；值本身的常驻量还能因插件复用没改的部分（新旧版本共享）进一步下降。
- 这是宿主内部改动、SDK 不变，画布 lane 现在就受益，不必等 part 级。


## 12. 时间轴：给插件 tick（速度映射 + 局部坐标）（已定形态，未实现）

**为什么**：用户画的东西多半跟着音乐走（第几拍），不是跟着秒走。按秒存的画布数据，part 挪到别的速度区段或改了前面的速度就和音符错位；
值宿主不解读，宿主没法替它换算 ⇒ 插件必须能自己在 tick 与秒之间换算。现状两侧都缺：画布只有横坐标 ↔ 秒；合成上下文**没有速度表**
（自动化轨是宿主把 tick 换成秒再给会话的），插件全程只见秒。

**一个事实**：钢琴窗的横轴是 tick 轴——横坐标 ↔ tick 线性，↔ 秒反而非线性（所以才有"逐像素采样"那条提醒）。

**形态**

```csharp
// 速度映射：局部 tick ↔ 全局秒。不可变、线程安全；画布、会话、合成快照共用这一个类型。
public interface ITempoMap
{
    double PosToTime(double pos);   // pos = 相对本映射原点的 tick；返回全局秒
    double TimeToPos(double time);
}

public interface ICanvasTimeAxis
{
    double TimeToX(double time);    // 全局秒：TimeToX(0) = 工程开头
    double XToTime(double x);
    double PosToX(double pos);      // 局部 tick：PosToX(0) = 这块数据的原点
    double XToPos(double x);
    ITempoMap TempoMap { get; }     // 当前映射，原点 = 这块画布数据的原点
}
```

两组换算都保留：`TimeToX` 可由 `PosToX(TempoMap.TimeToPos(t))` 组合出来，但按秒定义的内容（合成音素、合成参数、音频对齐、音素混合）
是一等公民，不该为画几条秒线先学局部 tick；插件按自己数据的单位选一组，不经另一单位中转。两组**都不承诺线性**：眼下横轴是 tick 轴、
`PosToX` 恰好线性，但钢琴窗以后若能切成均匀时间轴，线性的就换成 `TimeToX`。

合成侧：数据所属对象上挂普通属性 `ITempoMap TempoMap { get; }`，**不需要可通知**——速度改动走会话整体重建（见 `ISynthesisAutomation`
注释：时基变更不经区间通知），会话内映射恒定，重建后的新会话带新映射。合成快照里的对象直接带当时那份（不可变，后台线程可用）。
画布侧照旧：速度一改宿主重新调 `Render`。宿主内部 `TempoManager` 已有不可变快照（`ToTick` / `ToSecond`），包一层即可。

**定下的规则**

- **tick 局部、秒全局**：`PosToTime(局部 tick)` 返回全局秒。插件拿到的其余时间全是全局秒（音符 `StartTime`、自动化轨求值、音频段、
  `TimeToX`），秒也局部化就得自己再加偏移，等于把原点请回来。
- **原点由宿主给、插件不知道**：挪动 / 拆分 / 复制时宿主只换映射的原点，插件无感。不提供 `OriginPos`，也不让插件从 `XToTime(0)` 推断
  （拆分后右半的左边缘变了，合成侧也拿不到同一个左边缘）。
- **挂在数据所属对象上，不进全局**：速度表是工程数据，按 SDK 一贯做法经上下文给出（插件没有"当前工程"的全局入口）；
  同一入口给出的映射与该入口的其余数据同一版本（会话里与音符 `StartTime` 同一次提交更新，快照里与快照的音符同一时刻）。

| 数据 | 画布侧 | 合成侧 | 原点 |
|---|---|---|---|
| note 级画布 | `TimeAxis.TempoMap` | 音符代理上的 `TempoMap`（快照里的音符同样带） | 音符起点 |
| 音素级画布 | 同上 | 同上（所属音符的） | 所属音符起点（音素位置由排版决定，不当原点） |
| part 级画布（将来，§10） | 同上 | 代理对象上的 `TempoMap` | part 锚点（宿主内部另存偏移，平时 0；拆分 / 合并后非 0，插件无感） |

- **局部 tick 可以为负**：拆分后右半的原点仍在原处，它起点之前那段数据的局部 tick 是负的。插件读数据不能假设 ≥ 0。
- **插值域要声明**：按 tick 定义的内容画布里用 `PosToX` / `XToPos`，按秒定义的用 `TimeToX` / `XToTime`；不在横轴线性的那个域里
  的曲线逐像素采样（眼下即按秒的曲线）。插件自己的曲线在哪个域插值，
  画与合成必须同一个域，否则跨速度变化处对不上。§7 第 2 条届时按此改写。
- **暂不给**：拍号（按小节对齐网格等，以后纯加法补）；会话级的全局映射（原点 0，等有不属于任何对象的按拍子计算再加）；
  声明上下文里的映射（声明时按拍子算摘要等，等真实需求）。
- **命名**：秒 `Time`、tick `Pos`（术语表），方法统一 `AToB`，与现有 `TimeToX` 同风格。

**音高轴**（同批做）：`ITimelineCanvasHost` 与 `TimeAxis` 平行加一条 `ICanvasPitchAxis PitchAxis`（`PitchToY` / `YToPitch`，单位半音，
同音符 `Pitch` 与合成音高）。宿主**一律提供**，画布 lane 也有，不在声明里开关——用不到纵轴的插件不调就是了。参数面板当作迷你钢琴窗
（显示哪段音高由宿主界面定），钉进钢琴窗只是位置与范围变了，插件同一套代码。

**前景 / 背景**（同批做）：`ITimelineCanvasHost.IsBackground`（普通 getter，变化时宿主重调 `Render`，同 `Width` / `VisibleBounds`），
作背景显示时插件可简化绘制（如只画轮廓、不画文字），给前景参数让出视野。画布 lane 现在就有背景状态（宿主压暗、不收输入）。

**落地拆分**：画布侧（`ICanvasTimeAxis` 加 tick 换算与 `TempoMap`）改的是未发布 API，宜在画布合入 master 发布前做；合成侧（音符代理
与快照加 `TempoMap`）是已发布接口上的纯加法（宿主实现面），可同批或单独提。

## 13. 画布没有默认值（已实现）

宿主持有默认值，是为了在控件上显示"当前值"——没存值时拿它顶上；插件读到的照样是"没有值"，读值时传自己的默认值、自己对齐口径。
画布的值由插件自己画，宿主从不显示它，所以画布**没有默认值**：`CanvasConfig.Create(preferredWidth, preferredHeight, createControl)` /
`CanvasLaneConfig.Create(createControl)`，两者都不实现 `IValueConfig`（推翻 2026-10-27 的"画布默认值不能是 Null"）。默认值是插件自己定的，
宿主存起来再交回去等于绕一圈。

- **没设过 = 不存值**：宿主按原值读（`RawValueField(key, Null)` / `LanePath.ReadRaw`，不走按默认值类型过滤的 `GetValue`——拿 Null 作
  默认值会把任何存值都读成 Null），读不到就是 Null；插件读值时补自己的默认值。
- **恢复默认 = 删掉存值**（侧栏右键、part 预设重置）；侧栏兜底摘要"默认 / 已修改"= 没存值 / 存了值；预设抓取时没存值的画布保持没存值。
- **容器默认值**：对象 / 键控容器的默认值里不占画布的键（同按钮）；数组 / 列表里画布元素的位置上是 Null（位置必须有值）。
- **agent / 命令**：画布字段接受 null（= 清掉）；字段说明不再写 default，提示照当前值推断形状。
- 顺带修好：标签栏"有数据"圆点对画布 lane 原先用 `LanePath.Read(…, Null)`，被类型门读成 Null、永远不亮，改为按原值读。
