# 画布的叠放：参数区与钢琴窗工具（参数区、叠到钢琴窗上均已实现）

同一块插件画布可以出现在两个地方：参数区（钢琴窗下方的参数面板）和叠到钢琴窗上（**PianoOverlay**，铺在音符区上）。画布还是同一块画布，只是位置不同。两处用**同一种操作面**：
用户选的几块画布叠在上面、都能操作，最底下是宿主自己的编辑。行为只看画布本身，不看它放在哪——同一块画布放到哪都一样用。

前情：`canvas-in-parameter-panel.md` §10.4（方向与事件归属的修订记录）。本文定下两处的叠放形状，取代那里"画布不叠画布"的约定。

## 1. 共同的模型：一个操作面 = 一摞

- **上面**：用户选的画布，按顺序叠放，**全部显示、全部接收事件**。顺序用户可调。
- **最底下**：宿主的编辑——它也是一层，只是永远在最底、最后被问。
  - 参数区：激活的是画布时，宿主这层只剩 Shift 拉选区、选区菜单右键、中键平移。激活的是曲线 / 数值 lane 时例外：
    **激活的参数总在最上层**（绘制与事件同序），它的编辑（画线、拖锚点、拖 lane 值……）就是最上层，背景画布只作显示（见 §2）。
  - 钢琴窗：当前工具的行为（音符工具、音高笔……）。
- **所有画布都可叠**：插件文档统一约定"画布可能和别的画布叠在一起：大部分透明、只在需要的地方画、只在画了东西的地方接按下"。
  叠哪几块由用户决定；两块整片界面的画布叠在一起不好看，用户少开一块就是。暂不加"独占 / 可叠"的声明——真出现插件明确知道
  自己不能叠的情况再加（纯新增）。

## 2. 参数区

- **激活与可见脱钩**：激活的参数（含画布）总是显示，画布放在这一摞的最上面。**小眼睛**只表示"不激活时也留在这块面板里"，
  由用户自己开关；激活**不再**顺带打开它的小眼睛（原先会，于是切几次标签就攒下一串画布）。切走标签后，那块画布就不显示了，
  除非用户开着它的小眼睛。
- **去掉"画布不叠画布"**：可以同时开几块画布的小眼睛，它们全部画出来；激活的是画布时全部接收事件（原先只有激活的那块收输入）。
  激活的是曲线 / 数值 lane 时，背景画布不接收事件（2026-11-14 改定）：激活的参数在最上层，曲线编辑在面板里哪儿按下都要；
  原先背景画布排在它前面，铺得满的画布会挡住大片曲线编辑。
- **叠放顺序**：激活的在最上；其余开着小眼睛的先曲线类、后画布类，每类里越局部越在上——part 级（自动化曲线 / 时间轴 lane 画布）→
  note 级 → 音素级（铺满整块的垫底，只占自己那段的放上面，两者都看得见、点得到）；同一级按开启的先后叠，后开的在上（见 §7）。
- **回显轨**：显示只由标题栏的 chip 决定。原先"激活 / 开小眼睛时连带点亮同 key 的回显"一并取消——与激活和小眼睛脱钩同理，
  否则切几次标签回显也攒下一串。
- **曲线 / 数值 lane** 照旧：开着小眼睛的在背景压暗显示、不接收事件——它们的编辑就是宿主那一层，只对激活的那条生效。
- **`IsBackground`** 保留，含义从"不收输入"改为"不是用户当前激活的那块"：插件可以借此画得简单些（如不画文字）。
  背景画布与背景曲线一起由宿主调淡（2026-11-14 改定，原先不调、由各插件自己调淡，淡的程度不一）：整组按半透明画，
  而不是盖一层黑——背景参数淡下去，面板背后钢琴窗的透视不受影响。"多淡"归宿主统一，插件只决定画哪些。
- **时间轴画布的分界由宿主画**（已实现）：参数区里看不到音符本身，宿主在激活的那条 lane 上画各块的分界（各块的起止——音符 / 音素真实的边界 tick——按值去重——相邻两块共用的边、同时开始的和弦音符只画一条；全部块画完后盖在插件内容上面）；叠在下面的不画，
  免得几层分界叠成一片。插件不必自己画分隔。
- **音符重叠**（已实现）："后盖前"去重叠是人声合成的口径（单声部），只用于人声 part；**乐器 part 不去重叠**，每个音符按完整的时间区间出段，
  重叠的段叠在一起，和弦里每个音符都编辑得到（数值 lane 与时间轴画布同一口径）。数值 lane（宿主自己画、自己编辑）：
  重叠的段先画没选中的、再画选中的（选中的在上）；横扫写值 / 右键清除**有选中的音符时只改选中的**（扫过没选中的也不动，音素 lane 按所属音符算），
  没有选中时扫到哪改到哪（整个和弦一起调）。人声 part 同此规则。
  重叠的画布块叠放（已实现）：先按音符顺序放没选中的，再按音符顺序放选中的，后放的在上（命中顺序跟着放的顺序）。音符顺序是起点升序、
  同起点时尾巴长的在前，于是同起点的短的在上、长的在它结束后露出来，起点不同的后开始的在上、先开始的露出前面一截——每块都点得到；
  起止完全相同的靠选中区分。一处只有最上面那块收事件，它不接的交给宿主（下面的块要等"一摞层"的事件分派做好才会被问到）。

## 3. 叠到钢琴窗上（PianoOverlay）

- **两个视图，各叠一摞**（2026-11-14 定）：音符视图（音符工具）与音高视图（其余工具：画笔 / 锚点 / 固定笔刷 / 颤音）
  各有一套独立的一摞——有的画布只在其中一种编辑下有参考意义。切工具跨视图时，音符区上的画布与悬浮标签整排换成另一个视图的。
  （演变：最初每个工具各叠一组 → 11-13 改成所有工具共用一组 → 11-14 定为按两个视图分。）
- **固定层**：每摞里有一个宿主的固定层——音符视图是「音符」，音高视图是「音高」（合成音高、遮罩、颤音、最终音高线一组）。
  它就是当前工具所在的层：接住所有按下；它**之上**的画布先被问，不接的落到工具上；它**之下**的画布永远轮不到事件，只显示，
  宿主标 `IsBackground = true`。所以"哪些画布在音符 / 音高线之上、哪些垫在下面"就是拖动标签越过固定层。
  固定层只能拖动，不能激活、没有小眼睛。另一个视图的固定层由宿主放：音符视图里音高线附在音符正上方（音符工具下它只是不收事件的参考线），
  音高视图里音符垫在最底；它们任何时候都不收事件。
  默认：音符视图里音符在最底（画布都在音符之上，即原先的行为），音高视图里音高线在最上（画布都垫在音高线下，遮罩顺带把它们压暗）。
- **加上 / 取下**：悬浮标签最右的「+」（只要这个 part 有能叠的画布就在；没叠任何画布时标签条只剩它和收起按钮），弹一张勾选列表——
  这个 part 此刻能叠的全部画布，按参数属于谁分组，同参数区标签栏的勾选列表；点一项切换、菜单不关。加在当前视图那一摞：
  音符视图里放在最上（标签最左），音高视图里紧贴在音高线下面（仍垫在音高线下，要盖过它就拖到它左边）。
  参数区的标签按钮不加入口：它的右键已是小眼睛。动作面：`parameter.placeOnPianoRoll` / `removeFromPianoRoll`（画布作选择器参数）。
- **悬浮标签**：音符区右上角、时间轴下方，描一圈边与钢琴窗分开。标签与参数区标签栏同一个按钮——
  - **顺序 = 叠放顺序**：越靠左越在上（同从上往下读）。拖动标签排序，手感同数组控件拖序号条、轨道头拖拽：被拖的跟手，其余按新排布缓动让位，松手才写顺序。
    为此单击在松开时才算（按下可能是开始拖动）。
  - 单击 = 激活：**临时**画到最上、总是显示，不改标签与存储里的顺序；再点一下撤掉激活，回到它在顺序里的位置。
    激活与小眼睛脱钩（同参数区）：激活不顺带打开小眼睛。
  - 右键 = 小眼睛：不激活时显不显示。关了不画、不收事件，但还叠着。激活着时右键 = 撤掉激活并打开小眼睛（相当于再单击一下 + 开小眼睛），
    参数区页签同理（回到上一个激活的，它留在背景里显示）。
  - 最左的「>」把标签与「+」向右收起、只剩「<」，再点展开；收起展开带动画，收起状态记住。
- 存储：按"声源 / 效果器类型 + 画布"记（宿主内部 `PianoOverlay`，存 `PianoOverlay.json`；画布的键与标签栏隐藏同一份），
  两个视图各记叠了哪些、顺序（含固定层的位置）、各自的小眼睛、激活的那块，另记标签收起没有；跨工程生效（同参数面板钉选、标签栏显隐：界面偏好，跟声源走）。
  画布不再被声明时记录保留、不显示，重新声明即恢复。与标签栏隐藏互不相干：从标签栏藏起来的画布照样可以叠在钢琴窗上。
- 激活的画布不管在固定层哪边，都临时画到最上、收事件。固定层之上的画布 `IsBackground = false`（它们就是这块操作面的前景）。
- 都在框选框与波形带之下；只铺音符区（波形带显示着就到它上沿，否则到参数区上沿）。

| 种类 | 能叠到钢琴窗上吗 | 在音符区怎么摆 |
|---|---|---|
| 时间轴 lane 画布 `TimelineLaneCanvasConfig` | 能 | 铺满整个音符区 |
| 时间轴画布 `TimelineCanvasConfig` | 能 | 每个音符（音素级的每个音素）一块，横向 = 它的时间段，纵向铺满音符区 |
| 侧栏画布 `CanvasConfig` | 不能 | 没有时间轴，摆不进钢琴窗 |
| 只传值的条目（`Never` / `ValueOnlyConfig`） | 不能 | 没有控件 |

- **纵轴**：钢琴窗的音高轴，与参数区里"看向音符区的窗口"是同一套映射（`ICanvasPitchAxis`，n 号键占 [n, n + 1)）。
- **时间轴画布纵向铺满**：插件知道自己的音符在哪（声明时拿得到音高，纵轴映射也给了），自己只在需要处画、只在画了东西处接按下，
  宿主不替它划范围。音符在时间上重叠时（乐器 part 允许）各块也重叠，但音高不同、插件只在自己音符附近画与接按下，自然分得开；
  同一条 lane 的各块叠放同参数区：先没选中的、后选中的，各按音符顺序，后放的在上。
- **分界宿主不画**：音符本身看得见；要标出范围由插件自己画。

## 4. 事件（两处相同）

与 `ICanvasControl` 注释、插件文档"鼠标 / 键盘"两节同一套归属规则——一次拖动只归一个接收者，谁认领归谁，不交出不收回；每一层一视同仁：

- **按下**：自顶向下逐层问（宿主最后），第一个置 `Handled` 的认领；都不接，归属先不定。
- **归属未定时按着键的移动**：同样自顶向下逐层问，第一个认领的拿走；其余收过按下的层收到补发的抬起（按下位置，`IsClick = false`）。
- **一直没人认领就松手（点击）**：抬起同样自顶向下逐层问，第一个在抬起上置 `Handled` 的拿走这次点击；其余收过按下的层也收到抬起（成对），
  但 `IsClick = false`——一次点击只有一层处理。上面都不要的点击归宿主（如空白处单击取消选中）。
- **双击**：两次独立的点击，各自按上面的规则走。
- **"拖动时再认领"敌不过下层"按下就接"**（2026-11-13 定）：上层按下时不接（想等拖动），按下就轮到下层；下层在按下时接住，这次操作就归下层，
  上层只收到补发的抬起。严格按"谁先接住归谁"，规则可预期；想让某处的拖动归自己，就在按下时接住。否决：下层的认领先挂起、等上层表态——
  要缓存与补发事件，同否决"中途交出"的理由。
- **键盘**：按键给最近一次接住点击的那一层；按下时它没认领，再给外层（参数区 / 钢琴窗的快捷键）。归属同鼠标（按下定归属）。
- **悬停与指针形状**：由接住这次移动的那一层定；没有层接，用宿主的。
- **宿主先截的唯一例外**照旧：参数区里右键落在范围选区带内，宿主直接弹选区菜单。

**宿主这一层不改**（2026-11-13 盘点）：钢琴窗的工具几乎都在按下时就动手（音符工具按在空白处立刻取消选中、开始框选……）。它们是最底层，
上面的画布先被问：画布在按下时接住，这次操作就归画布；画布不接才轮到工具。"拖动时再认领"敌不过下层"按下就接"（见上）——
于是只想要"空白处拖动"的画布拿不到它，这是规则的预期结果，不为此把工具拆成按下 / 拖动 / 抬起三段认领。想要就在按下时接住。

**命中测试查询（可选，先不做）**：宿主在按下前 / 悬停时问插件"这个点是不是你的"。规则不变，只是宿主提前知道答案——叠放时直接定位
该问哪一层、悬停时的指针形状也能由它定。"逐层问按下"性能或体验不够时再加（纯新增）。

**实现**：两处共用一套"一摞层"的事件分派（取代现在 `Container` 只认一个子元素转给主组件的形状），参数区与钢琴窗各自只提供层的列表与宿主层。

## 5. 实例与值

- 同一块画布同时出现在多处（参数区、钢琴窗、多块参数面板）：各自是独立的实例、共用同一份值，一处提交后别处跟着重建——沿用现有的
  实例寿命契约（值一变实例作废、按新声明重建）。
- SDK 不加"你在哪里"之类的标志：放在哪都只是另一个入口。

## 6. SDK

不改接口。插件文档的约定改为"任何画布都可能和别的画布叠在一起"，`IsBackground` 的含义按 §2 改写。

## 7. 叫法与待定

- **PianoOverlay**（叠到钢琴窗上）：命名的是**位置**，不给画布另起名字——画布还是同一块画布，与在参数区的唯一区别是放在哪。
  动作"叠到钢琴窗上 / 从钢琴窗取下"；宿主内部 `PianoOverlay`，存储 `PianoOverlay.json`。带 Piano 前缀，与界面浮层
  （`ImagePreviewOverlay`、Avalonia 的 OverlayLayer）区分开。避开的词：
  - `Pin` / 钉选：参数面板的"把可钉属性放上标签栏"（`ParameterPinning`）；
  - `Stack` / 堆：已指参数面板多开的那一摞（`RegisterPanelStackActions`）；
  - `Layer` / 层：宿主内部的渲染层（`PlayheadLayer`、`RegionSelectionLayer`……）。本文说"一摞层"只是描述叠放，不作名字。
  已补进 `docs/naming-glossary.md`。
- **叠放顺序**：激活的在最上；参数区其余的先按级别（part → note → 音素，§2），同一级按开小眼睛的先后，后开的在上；
  钢琴窗上按用户在悬浮标签里排的顺序（§3），宿主不按级别重排。想提到上面就关了再开，或点它的标签激活。
  画布大部分透明、只在画了东西处接按下，顺序只在两块在同一处都画了东西时才有影响，而那时用户多半正在操作其中一块（已激活、在最上）。
  先不做专门的排序入口；不够用再加（参数区标签右键"上移 / 下移一层"）。钢琴窗上的标签可以拖动排序（§3）。
- 钢琴窗各工具的认领盘点已做（§4）：按"谁先接住归谁"，工具不改。
